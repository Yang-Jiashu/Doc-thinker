# 职场方法 · 毛选启发

这是 Doc-thinker 产品内的原创工作问题方法库，不是 Codex 本机技能安装包，也不是《毛泽东选集》全文资料库。`mao-workplace` 是保留的技术 ID，公开名称强调现代方法设计与历史启发的区别。

本项目原创的是知识单元的组织与操作规则，不是所引用的历史原文，也不声称其中任何通用方法世界首创。`authorship=project_original_method_design` 表示项目自行设计；`validation_status=design_unvalidated` 明确这些规则仍在开发和验证中，不能把单元测试通过等同于现实职场效果得到验证。

## 本地知识

查询 [knowledge.json](./knowledge.json)。四条稳定 ID 分别对应事实调查、主要瓶颈、试行反馈和协作调度。普通查询在本地完成，不需要联网读取原文，不执行脚本或网页内容。预算不足时整体舍弃单元，不截断规则或适用边界。

每个原创单元包含：

- `problem_pattern`、`task_signals`：对应什么任务，供匹配使用，不是强制启用指令。
- `required_facts`：判断前需要核实什么；事实缺失时先列缺口，不自行补造。
- `decision_rule`：可检验的候选判断规则，不是已证明有效的定律。
- `action_template`：产出什么表格、方案卡或汇报，而不是只给抽象建议。
- `stop_conditions`、`counterexample`：什么时候停止建议或不适用。
- `reasoning_role`：后台辅助推理的设计标签，不表示已经运行或得出结论。

每条卡片明确区分：

- `excerpt`：已按链接核对的极短历史原文。
- `commentary`：本项目原创现代方法的简要概述，不是毛泽东原话，也不是对用户情况的事实判断。
- `boundaries`：历史语境和现代使用限制。
- `source_title`、`source_url`、`published`：作品名、原文公开出处和作品日期；作品日期不是网站发布日期。

## 使用路线

Harness 根据当前任务选择知识型 Skill，不要求用户记住名字或选择独立推理模式。例如，项目延期且原因说法冲突可匹配事实调查，跨部门交接卡住可匹配协作单元。只有任务信号及问题内容相关时才纳入；低置信或没有相关内容时不启用，用户明确关闭或排除时不使用，也不要求每次使用全部四条。

先根据用户描述或上传材料梳理已知事实和信息缺口，再把命中的方法作为分析角度，最后给出可执行建议、适用条件和检查结果的方式。需要时用类比比较情境差异、用演绎检查前提、用归纳整理共同现象；这些都不能把方法参考升级为事实证据。

引用原创操作方法时标明为本项目设计；引用历史启发时展示对应书目来源，不能把整个现代规则归为毛泽东所述。用户材料的证据引用与本包来源分开。不得用此包证明用户公司发生了某事，或证明某个同事怀有特定动机。

## 内容边界

历史作品有具体政治和组织语境。这里只借鉴可讨论的方法角度，不把普通同事关系套成敌我关系，不提供操控、报复或侵犯隐私的方案，不用人物权威替代证据。现代建议须根据实际条件检验，不承诺适用于所有职场情境。

本包只包含原创方法设计、精选短引文及其出处，不包含全文。来源网页公开可读并不等于取得再分发授权；引入更多原文、版本或用户私有材料前，须单独处理权利与访问隔离。

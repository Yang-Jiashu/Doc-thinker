# 模型设置：先选择，再连接

分发范围：邀请源码 ZIP 只包含经过筛选的运行入口、文档和复跑脚本，不包含本文引用的全部历史实验 JSON、私有数据或开发测试。历史结果与完整开发命令请在完整 Git 仓库中查看；包内安装与自检以 [邀请部署说明](../deploy/invite/README.md) 为准。

在 `/config` 选择服务商，再搜索模型、填写该服务商的 API Key。预设自动带入连接地址；已有的自定义模型、代理地址和逗号分隔的多模型路由会保留，不会在页面加载时被替换。

## 界面如何组织

- **对话与理解**：对话、视觉、关键词、知识抽取四个角色，共用一套服务商连接和密钥。换服务商会联动这些角色，避免留下上一家厂商的模型 ID。
- **文档检索**：独立选择嵌入服务。已知默认维度自动填写；未确认维度的预设要求用户核对，不猜数值。
- **结果重排序**：独立服务，可关闭。候选列表不会混入对话或向量模型。
- 预设模型通过可搜索弹窗选择，显示模型 ID、能力和简要说明；自定义入口折叠在弹窗底部。高级地址与并发配置默认收起。

本地版本化目录为 `docthinker/ui/static/model_catalog.json`，现有 **13 个提供方/通道、73 个模型预设入口**：OpenAI、百炼、硅基流动、DeepSeek、Moonshot、智谱、MiniMax、StepFun 普通 API、Step Plan、Google、OpenRouter、Ollama、Jina。同一模型在不同通道是不同预设，不是 73 个不同基础模型。每项保留官方来源。目录只包含项目当前接口可表达的用途，不把图片生成或 Responses-only 型号混入对话列表。

原目录整体核查日期 `checked_at` 仍为 **2026-09-19**。**2026-10-10 只增量核对了两条 Step 5 Preview 预设**，日期及注意事项写在对应提供方说明中；不表示其他服务商重新核查，也不保证实时可用。

## Step 5 Preview：不要混用两个通道

| 选择 | Base URL | 额度边界 |
|---|---|---|
| StepFun 普通 API | `https://api.stepfun.com/v1` | 普通 API 按用量计费，与订阅 Credit 独立 |
| Step Plan | `https://api.stepfun.com/step_plan/v1` | 使用有效订阅的 Credit，不能用普通 API 余额推断套餐状态 |

两条预设的模型 ID 都是 **`step-5-preview`**，仅列入对话/视觉角色，不作为低预算关键词或知识抽取候选；辅助角色留空跟随对话模型时，仍可能使用它并产生费用。地址及模型参数依据 [官方 Chat Completions API](https://platform.stepfun.com/docs/zh/api-reference/chat/chat-completion-create)，通道/额度区别依据 [Step Plan 说明](https://platform.stepfun.com/docs/zh/step-plan/overview)。

官方模型支持文本、图片、视频输入、文本输出和 1M tokens 上下文。这是服务商的能力声明，**不是应用已经实现视频处理、工具执行或使用 1M 上下文**；已有上下文预算不因选择模型而扩大。详见 [Step 5 Preview 模型说明](https://platform.stepfun.com/docs/zh/guides/models/step-5-preview)。

多人内测或客户服务不能直接沿用个人订阅权限；将 Step Plan 服务提供给第三方需要厂商明确许可，依据 [付费服务协议第 3 节](https://platform.stepfun.com/docs/zh/step-plan/paid-service-agreement)。选择本地预设本身不会调用模型，也不验证账号权限或自动切换已保存设置。

**本人连通检查（2026-10-10，实名认证前）**：两个通道的模型列表请求均返回 HTTP 200；Step Plan 列表包含 `step-5-preview`。最初仅保留 HTTP 403 的笼统订阅/权限分类，不能据此判断套餐额度。随后按[官方推理接入示例](https://platform.stepfun.com/docs/zh/step-plan/integrations/reasoning-api)，使用真实 OpenAI SDK、相同正确路径及最少必要字段重新测试，验证前该密钥返回 **HTTP 403，`error.type=real_name_required`**：此免费 Step Plan 要先完成人脸实名认证。**普通 API 返回 HTTP 402** 是另一独立通道的 Credit/配额提示，不代表 Step Plan 额度不足。诊断脚本已保留明确实名前置操作，不输出密钥或任意服务商错误内容。模型出现在列表里仍不等于可以生成答案；这些结果只适用于当次密钥/通道，不代表其他账号。

**同日实名认证后复测**：使用 OpenAI SDK、同一 Step Plan 地址和 `step-5-preview` 已返回 HTTP 200、非空答案、`finish_reason=stop`；该短连接检查的供应商报告用量为 43 tokens。真实论文配对实验另行保存，不把短连接检查算作回答质量测评。此前 403 的记录是验证前的历史结果，不能继续当作当前连接状态。此测试仅证明当次本人调用接通，不代表第三方共享、商业服务授权或所有请求都能成功。

**真实论文配对实验（同日完成）**：4 篇原始论文、12 题各重复两轮，共 48 份真实回答，主实验供应商报告总用量 291,150 tokens。题目等权 AI 盲评分为关闭辅助 84.22、开启 82.40；不是人工测评或统计显著性结论。24 次开启辅助均未新增完整可用支持材料，因此不能把总 token 或耗时的小幅下降宣传成推理算法收益。实验输出上限显式设为 8192，产品默认仍为 2048；默认上限的独立试跑发生过空答案截断，费用记录另列。完整方法、缓存/顺序分层、逐题证据与限制见[实测报告](../benchmarks/research_real/result_real_20261010.json)。

## 私有研究模式：本地中英文检索

启用 `DOCTHINKER_RESEARCH_ENABLED=true` 的私有研究模式，可选用本地 `intfloat/multilingual-e5-small`，将语义候选与词面检索合并。它使用独立的本地配置，**不读取 `/config` 的 legacy GraphCore 嵌入服务设置或 API Key**。在项目根目录、运行服务的同一 Python 环境中执行一次：

```sh
pip install '.[research-semantic]'
python scripts/setup_research_embeddings.py
```

安装脚本仅下载公开模型。固定 revision 为 `614241f622f53c4eeff9890bdc4f31cfecc418b3`，ONNX 文件 SHA-256 为 `ca456c06b3a9505ddfd9131408916dd79290368331e7d76bb621f1cba6bc8665`；运行前校验模型及分词文件清单。默认目录是 `~/.cache/docthinker/research-embeddings/<revision>`。自定义目录使用 `python scripts/setup_research_embeddings.py --output /absolute/model/path`，并在服务启动环境设置 `DOCTHINKER_RESEARCH_EMBEDDING_DIR=/absolute/model/path`；目录必须是安装脚本生成的完整目录。

| `DOCTHINKER_RESEARCH_SEMANTIC` | 行为 |
|---|---|
| `auto`（默认） | 尝试使用已安装的本地模型，缺失时退回词面检索 |
| `local` | 显式启用相同的本地路径；仍保留失败降级，不自动下载 |
| `off` | 关闭本地语义检索，仅使用词面检索 |

检索运行期仅访问本地模型，不联网、不消耗供应商 token；最终回答仍使用所配置的 LLM。模型和分词文件约 487 MB，另需 CPU、运行内存与向量缓存。文档解析后预热只编码文档，查询时才编码问题；首次模型加载、建索引和热查询的时间分别记录，不能把本地计算称为零成本。

进程内只允许一个本地嵌入任务实际运行，忙时立即降级；前台等待超过 1 秒也改用词面检索。超时不等于杀掉线程，原任务完成前继续占用工作位，避免积累后台任务。缺模型、忙或超时分别记录 `model_not_installed`、`busy`、`timed_out` 等 trace 状态，并保留 `semantic_retrieval_unavailable` 提示；不可把这类回答当成成功使用语义检索的结果。

有界缓存按存储空间、会话、模型版本和正文哈希隔离；只接受当前仍有效的原文，撤回资料后旧向量或候选 ID 不能恢复引用。语义分数仅表示候选相关性，不证明原文支持某个结论。历史文档仍保留旧分块；需要新的完整句窗口时，请在新项目重新导入资料，系统不会自动改写历史文档或引用。本段是配置与运行边界说明，新增实现的实测结果应单独报告，不改变上面 48 份回答的历史结论。

### 句子窗口与后台整理的边界

**发布策略：普通服务入口默认关闭额外证据整理。** 跨语言检索、完整句引用与溯源修复仍生效；只有运营者在启动环境显式设置 `DOCTHINKER_RESEARCH_CONTEXT_ASSIST=true` 或 `1` 才开启实验性后台整理，`false` 或 `0` 关闭，非法值拒绝启动。普通用户无需选择推理模式。邀请码部署的 Compose 和用户 worker 也透传该受控开关；修改后需重启。低层 `ResearchService` 保留原构造接口，评测脚本显式构造 ON/OFF 两组，不受此服务发布默认值影响。

该默认值来自真实测试中暴露出的背景噪声和未补齐关键机制问题，不能把未通过质量验证的扩写作为默认卖点。它不是关闭最终回答、资料检索或用户确认记忆，也没有改变服务商模型。

新导入文档按完整句及相邻限定条件打包，存储目标为 2000 字符，单个不可分语句硬上限为 8000 字符。检索不是直接把存储块全部塞入模型：本地语义编码使用 256 tokens 的滑窗、192 tokens 步长，问题编码上限仍为 448 tokens。最高相似度对应的**原文字符位置**会传给选句器；基础引用窗口最多 1000 字符，避免命中后半段却引用无关的前半段。

**旧 v3 / legacy 整理路径：**只在确有未展示的原文时补入连续句子，可将同源窗口扩至最多 1600 字符；仍遵守合计 8 个来源、12KB 原文、24KB 完整提示预算。该路径保护至少 6 个基础来源，并检查替换是否丢失原有问题要点和独立证据，不确定时保留原来源。它保留可识别的前文主语、条件、否定与章节边界，不跨空缺拼接句子。没有新材料就跳过，不能把重复包装算作效果。下述历史实验测的是这一代实现，不是后面的新证据重选算法。

这些都是有边界的检索与文本规则，**不是语义蕴含验证或自动因果证明**。PDF 跨页、复杂表格及不规范排版仍可能切断主语和限定条件；较泛化的科研措辞也可能获得较高语义相似度。原文组织索引不作为新的事实、因果边或长期记忆写入。辅助流程运行期不调用 LLM，最终回答调用一次；更多原文会增加输入 tokens，不能因辅助本身不调用模型就声称整体更省 token。

第一轮修复后复测见[26 次真实调用报告](../benchmarks/research_real/result_repaired_20261010.json)：跨语言检索已能找到来源，但当时仍未补入新支持材料，不能把评分波动算成辅助收益。后续窗口定位实验使用预先固定的失败题子集，单独报告，不与这轮或旧实验混算。

**最终窗口实验（2026-10-10）**：4 道已知问题各一对回答，另有 1 道中文诊断，共 10 次真实 Step 5 Preview 调用、66,372 tokens。4 道主问题中，3 道实际补入原文组织材料，1 道提示完全相同。AI 盲评分 OFF 77.19、ON 71.25，开启组 1 胜、2 负、1 平；平均总 tokens 6605.5 / 6664.25，平均完整响应 47.19 / 40.57 秒。后者有缓存命中差异和输出长度差异，不能称为算法提速。该小型失败题开发集不代表一般用户分布，但已不足以支持默认上线额外扩写；具体错误、初始化成本、原始回执和限制见[最终窗口实验报告](../benchmarks/research_real/result_window_20261010.json)。这轮仍采用 8192 实验输出上限，产品默认 2048 未改。两轮本次修复实验合计 36 次真实调用、217,137 tokens，不含此前历史实验或 AI 评审自身的消耗。

### 新实验路径：分要点召回、本地重排、预算内重选证据

2026-10-10 的 `faceted_evidence_selection_v2` 已接入研究服务。它不再保护旧前 6 条来源，而是重新挑选实际送给回答模型的原文，允许替换低价值背景，不强行凑满 8 条。v2 还修复了 v1 将一个子问题的精排分数广播给其他子问题，以及概述一次命中就过早耗尽选取收益的问题；这是计算逻辑修复，不等于已经验证答案更好。用户仍正常聊天和写作，不需要选类比、演绎或归纳模式。普通服务的发布开关仍按上文管理；代码接通不等于质量已验收。

在已安装本地嵌入模型的同一环境中，显式安装重排器：

```sh
python scripts/setup_research_reranker.py
```

模型是 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`，固定 revision `1427fd652930e4ba29e8149678df786c240d8825`；ONNX 文件为 `onnx/model_qint8_arm64.onnx`，SHA-256 为 `1825907d6c1a9001ff78124780bbde20a614a8c3df3b63409cf3c72c6fe5c8b4`。安装脚本及运行时检查固定的模型、配置与分词文件哈希。默认目录为 `~/.cache/docthinker/research-reranker/<revision>`；自定义目录可用 `python scripts/setup_research_reranker.py --output /absolute/model/path`，启动时设置 `DOCTHINKER_RESEARCH_RERANKER_DIR=/absolute/model/path`。服务运行期不自动下载，不能仅复制 ONNX 文件而省略清单与分词文件。

启用本路径需要本地语义检索（`DOCTHINKER_RESEARCH_SEMANTIC=local` 或 `auto`）及 `DOCTHINKER_RESEARCH_CONTEXT_ASSIST=true`。它与 `/config` 的 legacy 远程重排服务独立，不使用远程重排密钥；关闭本地语义检索的兼容路径仍可能使用旧整理器，不能将其结果标成新算法实验。

| 阶段 | 实现与硬边界 |
|---|---|
| 需求拆分 | 基础计划只取问题原有文字，最多 8 个 facet、32 个显式技术锚点；可选查询翻译最多加入 4 个派生英文 facet，总数仍不超过 8，完整原问始终保留在首位；不从标准答案或论文生成扩展事实 |
| 补召回 | 各要点分别检索；明确点名的资料各有候选配额。候选以最多 3 个连续原文单元形成窗口，最长 1600 字符；过滤可识别的参考文献与致谢，保留原文位置 |
| 本地重排 | 每个候选只分配一个最相关的问题 facet，可为原文字或明确标记的派生译文；所有要点合计最多 48 对，不是每个要点 48 对。问题最多 192 个模型 token，每对最多 512，输出为未校准相关性分数 |
| 证据重选 | 只向实际评分的要点/文档维度计分，第一、第二份非重复材料按 1/0.4 提供收益；单一子句且至少两个技术锚点才允许 0.2 的第三份。锚点用于不足诊断，不当作语义证明。惩罚重复和长度，最多 8 个来源、12000 UTF-8 字节原文；最多 2 个基础来源获候选提名，不强制入选，仍占 48 对预算。选择不足时保留缺口，不用无关背景填满 |
| 回答 | 保留完整提示 24576 字节上限；辅助不生成新结论、不附加组织说明、不写记忆、不增加生成式 LLM 请求或供应商 token。正常生成答案仍调用一次模型；明确缺乏资料依据时可不调用 |

有作用域的分数缓存按存储空间、会话、模型版本、问题与正文哈希隔离，最多 4096 条。辅助前台等待上限为 8 秒；服务内只允许一个实际辅助工作线程占位，重排器另有进程级单槽保护，忙时不排队。模型缺失、推理失败或超时回退到基础检索，不转入旧扩写器；超时线程未完成前仍占位，不能据此堆积任务。**完成筛选却找不到可用证据不是故障**，这种情况返回缺口，不恢复已剔除的旧背景。

重排文件约 136 MB，此外仍有冷加载、CPU 推理、运行内存及缓存成本；与嵌入模型同时使用的进程占用更高。48 对是计算预算，不保证所有硬件都在 8 秒内完成。冷启动、热查询和并发退回须分别测量，不能把“不调用供应商”写成“零成本”。最终输入、输出及推理 token 由真实回答决定，新算法不预先承诺更省 token 或更快。

相关性与覆盖代理分数**不等于上下文足够、语义蕴含成立或因果链已验证**；原文中存在却未进入候选窗口的关键句仍可能漏掉。算法与相关工作的区别见[本轮证据重选设计](RESEARCH_GROUNDED_DESIGN.md#0-2026-10-10-已实现的证据重选路径)。

**真实评测结论：尚未通过质量放行。** 新路径 v1 / v2 各完成 18 次真实 Step 5 Preview 请求，合计 175,412 tokens，与上文旧窗口实验分开。最终 v2 的 8 组主问题中，ON 均实际完成辅助、没有超时、没有额外供应商请求；平均总 tokens 从 6545.875 降至 3627.625（约 -44.6%），但 AI 盲评均分 74.06 → 71.41，严格完整事实覆盖 9/23 → 6/23，全无关标签 7/64 → 9/37。不能称为已经解决漏召回或噪声问题，也未因此改变普通服务的实验开关默认值。平均完整回答 44.93 → 30.80 秒包含输出长度、供应商缓存及网络差异；本地模型前处理反而约 0.074 → 3.299 秒，不能宣传为单纯算法加速。实验输出上限仍为 8192，产品默认 2048 未改。8 道题、每组一次生成、AI 盲评仅是小型先导；四道新问题来自相同四篇论文，并非未见语料泛化。详情及跨轮评分不确定性见[完整报告](../benchmarks/research_real/result_faceted_20261010.json)和[结果解读](RESEARCH_GROUNDED_DESIGN.md#04-真实论文结果工程修复不等于质量修复)。

### 可选本地中文查询翻译：不翻译证据

为中文问题检索英文论文提供一个有界英文查询分支，不生成答案、不翻译论文，不把译文写入来源、引用或记忆。原中文问题、原始显式锚点与点名资料范围保留，最终答案模型仍接收原问题；派生英文 facet 仅影响召回与原文精排，不能引入原问未点名的新资料范围。这是待独立评测的检索假设，不能从多语言模型标签或译文通顺推断质量提升。

在项目根目录执行以下实际命令；服务运行依赖只有可选 extra 中的 `ctranslate2==4.8.2`、`sentencepiece==0.2.2`，第二行是**显式转换阶段**额外使用的构建依赖：

```sh
python -m pip install '.[research-translation]'
python -m pip install 'transformers==4.57.6' 'torch==2.14.1' 'sacremoses==0.2.0'
python scripts/setup_research_translation.py
```

这组固定构建依赖已在 Python 3.11 / macOS arm64 验证。可以在独立构建环境运行安装脚本，再把**完整产物目录**交给只安装运行依赖的服务环境；运行时不会导入 torch、Transformers 或 Hugging Face 下载客户端，不会自动联网补模型。脚本的 `--help` 列出唯一可选路径参数：`python scripts/setup_research_translation.py --output /absolute/model/cache`；服务环境相应设置 `DOCTHINKER_RESEARCH_TRANSLATION_DIR=/absolute/model/cache`。输出目录必须在源代码仓库外，拒绝符号链接目录或资产，不能只复制 `model.bin`。

模型为 [Helsinki-NLP/opus-mt-zh-en](https://huggingface.co/Helsinki-NLP/opus-mt-zh-en)，固定 revision `cf109095479db38d6df799875e34039d4938aaa6`，许可 **CC-BY-4.0**。默认产物目录为 `~/.cache/docthinker/research-translation/<revision>`。安装按[官方 CTranslate2 Marian 转换方式](https://opennmt.net/CTranslate2/guides/transformers.html#marianmt)从约 312 MB 原始权重构建 int8；本次完整产物为 **82,483,716 字节**，另有构建依赖、下载暂存和运行内存成本。目录包含分词器、词表、配置、署名文件及清单，保留作者、来源、许可链接和转换/量化修改说明；固定源文件 SHA-256，运行时校验完整产物清单与哈希。

查询算法版本为 `opus-zh-en-ct2-int8-query-v2-protected`，资产格式为 `opus-zh-en-ct2-int8-query-v1`。本次构建 `model.bin` SHA-256 为 `e4955858cae9542bef37424a9b79720e3db2f32501fe62264c0cd3eac6319777`；不同平台或转换依赖可能产生不同哈希，不能冒称全平台产物相同。trace 保存实际 `model_sha256`、`manifest_fingerprint` 与耗时，不记录问题、译文、私有路径或异常内容。

| 边界 | 行为 |
|---|---|
| 输入与推理 | 原问最多 8192 UTF-8 字节；送入模型最多 256 个 source pieces（含 EOS）；生成上限 256 tokens，触及上限即回退；确定性 beam=1、2 个 CPU 线程 |
| 术语保护 | 最初将原问自带的英文短语与数字替换为最多 24 个占位符；只翻译一次，要求占位符完整、恰好一次且顺序不变，然后原样还原用户文字，不纠正错拼、不补否定词 |
| 检查与回退 | 还原后检查数字、英文术语及可识别否定线索；占位碰撞/缺失/重复/乱序、超限、模型缺失或校验失败、推理异常均返回原问题。无中文直接跳过；只有 `ready` 且译文不同才启用英文分支 |
| 并发与缓存 | 进程级单槽非阻塞 gate，忙时立即返回原问；LRU 最多 128 条，按存储/会话命名空间、模型版本和产物、问题哈希隔离。仍受上层辅助总等待预算约束，不另加一次付费回答 |

该分支随本节本地语义与证据辅助路径使用已安装模型；未安装 extra 或资产不会触发下载，而是保留原问题路径。占位和词法检查**不是语义保真验证**：虚构问题实测中，中文“不能预测风暴”仍可能变成只说“结果不可预测”，即使术语、数字和否定表面检查通过。因此 `semantic_preservation_verified=false`，不能把 `ready` 理解为完整保留了约束。

仅作部署参考：Apple M5 / 16 GiB 上三条虚构混合多要点问题，首条含校验加载约 0.574 秒，热运行无缓存分别约 0.250 / 0.249 / 0.698 秒。这不是 p95、并发承诺或真实论文质量结果；本地翻译新增 CPU 和内存开销，后续应单独报告冷启动、热查询、回退率、实际证据与答案质量，不与前述历史实验混算。

## 保存与凭据边界

1. 选择和搜索只访问本地目录，不调用模型，不拉取第三方列表，不消耗模型 token。
2. API Key 输入框始终为空，不回填原密钥；同一连接留空保留。切换服务商或修改地址清除尚未保存的输入，后端也要求为新目的地显式提供密钥。
3. 保存是原子更新 `.env` 并记录待重启状态，不把新模型 ID 混到旧客户端里。页面明确提示重启，不自动中断任务。
4. 环境别名同步保存。对经设置 API 保存的标准服务端连接，host/key 绑定用于检测外部环境与文件配置混配；冲突需要修正，不能静默把旧密钥发给新地址。此保护不是全仓库所有实验脚本的凭据治理。
5. 更改嵌入模型或维度需要重建已有向量。页面只警告，不自动删除、迁移或重建数据。

设置 API 会写入服务器本地 `.env`，不是企业级密钥保险库。部署给客户前仍必须配置管理员鉴权、HTTPS、访问权限与凭据管理；不要将无鉴权开发服务暴露到公网。

## 不能省略的兼容性条件

- **账号/地区**：预设不表示已连通、免费或账号已开通。API 计费通常独立于聊天产品订阅。地区与实际可用型号以服务商为准。
- **百炼**：新文档的 workspace 地址带 `{WorkspaceId}`；选中后必须补全，未替换不能保存。已有通用地址不会自动迁移。
- **Claude**：本目录提供 OpenRouter 入口，使用 OpenRouter 的密钥。不能把 Anthropic 原生密钥填给 OpenRouter。原生 SDK 或官方兼容层没有作为本轮预设单独接入。
- **Ollama**：需自行启动服务并下载相应模型；本地无鉴权连接可用 `EMPTY` 占位。界面不会安装模型。
- **视觉**：只筛出声明有读图能力的型号。选择“跟随对话模型”不代表文本模型自动获得视觉能力；未确认时会警告。
- **结构化抽取**：目录中的关键词/抽取角色是接口与任务适用性筛选，不是准确率承诺。思考型模型未必适合低延迟抽取，需评估实际输出与成本。
- **向量**：仅对已明确支持维度参数的官方模型传递 `dimensions`；未知接口使用服务器默认并校验返回形状，不裁剪或填零伪装成功。
- **重排**：按照返回结果的原始 `index` 映射文档，非法/重复索引或非有限分数明确失败。自定义服务需要兼容当前请求和返回格式。

预设与设置控制器的契约测试使用离线 mock 和本地模拟 UI，不访问服务商；与上面的本人连通检查分开，不能把离线测试通过当成真实 API 成功。新增预设时应核对官方模型 ID、接口、模态、维度和适用角色，并记录对应核查日期、更新契约测试，不只添加显示名称；局部增量核对不能把整体 `checked_at` 改成新日期。

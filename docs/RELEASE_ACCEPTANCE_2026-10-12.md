# DocThinker 邀请测试软件验收 2026年10月12日

本版交付可部署的邀请内测源码，适合在受控环境验证私人研究助手；不等于公网已发布或商用质量认证。默认只开放聊天和历史，研究核心须由部署者及账号明确开启。

本文保留10月12日各轮历史，最后的软件修复与复验更新于10月13日；新的测试和补丁不回写为旧模型实验成功。

## 已修复的软件问题

- 原文筛选不再只保护旧关键词排名：整段参考表和明确纯背景先过滤，问题命中与方法结构共同提名，再选择互补的文档、需求和主题。结构解释任务单独保护有出处的组件功能定义与原文明示的有序过程；提过名字不等于解释过，数值比较不自动扩成架构问题。最多扫描 4,096 个片段、48 个候选；基础 8 条来源，可选 Insight 再补 2 条，全部共享 12,000 原文字节预算。
- 相同材料重新导入不会因随机标识改变入选内容；明确比较两篇文档时，相同表述保留各自出处，不能当成两个独立实验证据。未覆盖指定文档、达到扫描上限、句尾不完整或缺回指对象会保留缺口提示。
- “为解决这个问题”一类回指与可见的前一句和条件绑定；超长绑定单元不能删掉前提后单独选操作。所有节选仍是原文连续切片，不能拼接跨页文字冒充原句。
- 回答合同要求逐主张引用及对象、任务、指标、对照和条件绑定；提出实验时，改变项、固定项、替代解释和反证必须对应。合同和词面检查不证明模型遵守或语义正确。
- 多个英文原词在所引节选缺失却在其他本次节选出现时，逐主张核对提示可能挂错引用；不自动换标签，也不判定支持。来源边界、回指和扫描缺口在聊天与复制记录中保留，使用固定说明，不转述上游任意消息。
- 多来源逐字对应要求所有引用的当前原文、坐标与完整表述一致；坏引用被过滤、超过核对窗口或尚有问题提示时，不能靠剩下一个好引用显示逐字核对标记。程序核对仍不证明语义支持。
- 补查即使在短片段内，也不跨已观察到的真实章节边界；最终拟合后重新检查可见开头回指，不将下一任务标题当成上一续文的对象。它不解决所有隐式换题、跨页缺失或模型语义错归。
- `[S5, S8]` 一类组合引用统一解析；未知标签、来源与方法标签混用、限流和异常元数据不能被静默丢掉后显示已核对，截流标记保存及重启后仍保留。正文不改写；所有实际来源仍参与撤回保护，旧漏洞不是权限绕过。
- 逐主张核对不再只截开头：仅跳明确的格式标题和纯列名，未知粗体、数字、否定和引用保留；原有12段额度按语句位置分层，800字符及每段三引用上限不变。未选语句仍计入遗漏，不是全文核验，也不自动判事实正确。
- 最终入模节选可附至多4项、1200字节的组件功能原句定位，只有结构/功能任务启用，不重复原文或生成定义；预算不足先整块去掉定位数据再减少资料。证据哈希对应实际拟合版本，词面定位不表示模型已解释完整。
- 效果、优越性和已证实的中英文词面优先进入同一12段核对窗口，非逐字主张提示逐任务检查指标、对照和条件。否定、条件及未知措辞仍保持待核对；不因某个混引来源有结果就放行整句，不自动判错或重写答案。
- 十条来源在 API、保存、客户端与撤回中统一支持；禁止上传的账号不能绕过界面重新解析。上传与重解析共用解析次数限制，不重复计算原文件字节。
- 配置损坏时仍可查看和停止固定部署项目；启动仍须完整验证。项目摘要支持确认后下载或逐段复制，不静默截掉尾部，也不自动创建公开链接。
- 部署包新增 `pack.py --verify ZIP` 只读校验：检查允许构建项、清单、逐文件 SHA256/CRC，拒绝篡改、路径越界、重复项和符号链接，不解压或执行包内代码。需要另外核对可信渠道的整包哈希；内部清单不是发布者身份认证或生产验收。
- 未注册账号的邀请码到期后可由管理员原子重发，旧码立即失效，原身份、权限及资料不变；已注册或撤销的账号不能重置，未增加公网管理接口。注册和重发竞争在同一事务锁下处理。
- 新版协议账号在撤销、停机并确认用户名后，可由管理员先冷导出完整当前业务文件和原始资料，再执行 live 资料清理。supervisor 与目标 worker 两级锁阻止运行中维护，旧协议账号主动拒绝；失败保留清理状态、可恢复重跑。保留不可复用的账号/端口记录，不是全身份抹除、物理擦除或备份/供应商删除，未操作真实账号。
- 自然材料请求按完整技术文件名与受限后缀绑定，不把普通短词或正文碰巧提及当成授权范围；显式材料子问优先占有限配额。原文数字章节继承有限方法/实验角色，互补小节在原有池中竞争，角色命中不能当事实成立。示指名词保守绑定同节紧邻前文，不能跨标题、图注或过滤间隔拼接；超长完整单元排除并披露，源首缺对象仍告警。
- 决策方法包 v2 与动态试点检查要求基线/对照、样本期限、指标测法、通过/停止/数据不足三类条件；建议阈值注明待确认，不冒充用户授权或论文结果。移动端目录严格使用当前 v2，旧 v1 只允许历史快照；未知版本不接受。实际仍是一次生成，方法检查并非语义验证或自动执行许可。
- V14b 后新增有限 TrialSpec 交付合同，只有当前明确的试点请求启用，不增加独立推理模式或模型调用。两臂配置按 JSON 类型比较，计数率使用全部计划问题作分母，有限区间检查无重叠／空档；未知、超限或不合规对象只作草稿。表格由程序渲染，自由正文的语义一致性不在校验范围。回执和所有实际来源一起撤回，手机状态回放不得复用旧的通过状态；详见[结构及范围](RESEARCH_GROUNDED_DESIGN.md#015-2026-10-13-把明确要求的试点交付变成有限对象)。

检索、整理、记忆修改不新增供应商生成请求；普通生成回答最多一次模型调用，不自动重试或切换模型。每服务仅一个非排队辅助任务槽，词面路径前台最多等一秒，超时计算真实结束前仍占槽。提示上限为 24,576 UTF-8 字节；输出按普通聊天 2,048 或研究 8,192 tokens 选择。字节预算和零额外调用都不等于实际 token 更少。

## 软件验证结果

- 10月13日本机按哈希锁安装的全新受限部署环境完整执行当前 `product-contracts` 后端命令：**3,993 passed，3 skipped，4 subtests passed**（51.53秒）。三项跳过仅为缺少可选本地神经运行依赖的真实模型烟测；对应模拟、预算与契约测试未跳过。`pip check` 无冲突；不是远程 GitHub Actions 或目标容器验收。前一轮3,484项记录已由本轮新增检索、请求边界与交付测试覆盖，不将它冒充最新计数。
- 新 TrialSpec 模块70项、真实服务接线36项、独立验收40项均纳入上述命令。独立检查实际发现并修复局部否定误触发、布尔与数字配置被视为相同、超大整数溢出三类缺陷，原反例保留；没有用测试数量代替模型质量。
- 移动客户端离线交互、隐私与渲染再次执行：**797 passed**（3.46秒）。H5、微信和 App 资源构建通过；构建不等于扫码、签名安装或小程序发布。

## 真实回答质量

10月12日的三组开发对照使用四篇固定公开论文和真实 `step-5-preview`：六次均完整交付，总上报 53,504 tokens。比较只切换动态 Insight，普通辅助和静态方法卡两臂均开。

核心方法已进入答案，动态补查带来一些有效控制信息；但 AUTO 合计 30,832 tokens，OFF 为 22,672，增加约 36%；平均完整响应 79.741 秒对 47.447 秒。还发现实验对象错绑、方案对照不闭合。因此本轮**不支持整体更准、更省、更快的宣传**；运行后的回指和回答合同修复不回写为这轮成功。

## 对外试用前的条件

需要目标服务器、可信 HTTPS、厂商分享权限与实际硬费用限制、手机外网验收，以及目标容器中的密钥挂载、持久化、备份恢复和并发验证。没有这些条件，不应向客户承诺生产可用。

新账号的冷导出/资料清理仍缺旧协议迁移、Docker 数据卷实际维护、全部身份抹除、备份及供应商记录处理；项目摘要本身不是全文档或聊天归档。扫描 PDF 没有 OCR，默认词面路径不能保证跨语言或任意改写的关键证据召回。确认记忆可扩容并修订，但不等于无限存储、自动偏好学习或 RSI；策略采纳和回滚闭环仍未全部接通。

## 1. 独立品牌与产品承诺

**DocThinker：围绕你的长期项目，把资料变成能核对、能修改、能接着做的成果。**

研究、写作和知识工作是首个场景，而不是要求用户学习的一套算法界面。用户描述要做的事情；后台负责有限范围的检索、上下文组织、状态管理与来源核对。类比、演绎、归纳不成为三个独立操作模式，也不能替代原文证据。

产品要让用户始终能回答三个问题：

- **从哪里来？** 答案能打开资料出处；来源失效、片段截短和未核验改写不隐藏。
- **为什么记住？** 项目要求由用户保存，记忆由用户确认；收藏一个答案不等于认可它的真实性。
- **这次做了什么？** 能看见真实回执与成果，不用动画或虚构的 Agent 步骤代替执行状态。

沿用 DocThinker 名称与现有品牌标识。借鉴 WorkBuddy 和 Manus 的任务入口、成果组织与可控上下文，不复制其商标、页面素材或专有代码，也不在对外界面把自己包装成两者的兼容版本。

## 3. 本轮工作台的交付范围

项目要求可在普通聊天中保存；成果收藏的读取和新增需要显式启用研究核心，以便重新检查来源。普通邀请聊天、离线演示与未开放功能仍需保持区分。服务不可用时，不能显示伪造的保存成功或研究成果。

| 能力 | 本轮行为 | 不代表什么 |
|---|---|---|
| 项目要求 | 在当前项目持久保存目标、输出格式与限制，带版本冲突检查；用户主动加入提问草稿 | 不默认注入每轮上下文，不改成系统高优先级指令，不自动学习偏好 |
| 四个任务配方 | 选择入口后生成可编辑的问题草稿；准备草稿不调用 LLM，用户发送才执行 | 不是四种新增模型，不是后台启动四个 Agent，不自行更改实验开关 |
| 真实执行回执 | 复用已有单次请求的提交、进行中、完成和结果未知处理；持久步骤各有稳定请求身份 | 不把未知当未收费，不自动重试，也不伪造检索完成百分比 |
| 持续研究任务 | 最多 6 个分析问题及依赖，用户批准 1–6 次尝试；保存检查点，重启后明确批准继续；按资料范围及下游失效 | 不是自主规划、无限续跑或任意工具执行；完成状态不证明答案正确 |
| 版本化任务报告 | 当前可访问回答按已保存步骤版本本地组装，保留各节来源定位，无额外总结模型 | 不是语义一致性核验；旧版失效后不回显其正文，不静默替换成新版本 |
| 成果收藏 | 保存当前项目内已保存答案的引用；目录只返回元数据，打开单条时重新校验答案与来源 | 不复制一份永不过期的证据，不证明答案正确，不自动变成长期记忆 |
| 显式确认记忆 | 继续使用已有确认、修订与来源失效规则 | 不从收藏、浏览次数或用户点赞推导事实可信度 |

四个任务配方是“对比资料、带依据写作、继续项目、复核结论”。生成的文字始终只是草稿，可以删除或改写；已有提问时由用户选择追加、替换或保留原草稿。界面上的项目说明也不是权限凭据：换项目、退出账号、页面重新加载后，仍以服务端身份与记录为准。

## 4. 骨架由代码负责，模型负责表达

本轮不通过新增规划模型、反思模型或多个并行 Agent 来完成工作台交互。新增产品状态尽可能使用确定性规则，复用现有研究服务。

### 4.1 项目要求：有限文本与乐观并发

项目要求是用户管理的工作约定，不是来源事实。保存时进行身份、项目范围与长度校验；提交携带预期版本，只有版本仍匹配才更新。两个页面同时修改时返回冲突，不能后写入的内容静默覆盖先保存的内容。

当前文本限制为目标 1,200 字符、输出格式 400 字符、限制 1,200 字符；初始版本为 0，保存成功后返回新版本。版本冲突使用 `409`，客户端应重新读取、检查差异后再保存，而不是无条件覆盖。

内部存储键同时绑定人可读的会话编号和知识库的稳定实例 ID。删除会话时先清理该编号各代的工作台元数据，清理失败则阻止删除；即使旧请求晚到，新建项目复用同一编号也不会读取旧实例的简报和收藏。这个隔离依赖后端身份与实例命名空间，不依赖前端显示的项目名称。

模型只有在用户把要求加入本次问题并发送后才会看到它。文本与问题一起经过现有输入预算；不能为了塞入项目要求悄悄放宽上下文上限。要求不能绕过资料权限、模型调用权限或安全约束。

### 4.2 任务配方：确定性草稿，不额外计费

任务配方只组织用户目标、当前可用项目要求与输出提示，不做隐含检索或模型调用。它不决定事实答案，也不把所有论文、全部记忆或原始聊天记录拼进提示词。

真正发送后仍走现有检索与回答路径。新工作台不改变研究辅助的默认开关、候选规模、来源上限或供应商调用次数。有限字节预算不是精确计费 token，也不是费用金额硬封顶；模型的真实 usage 和未知结果需要分别核对。

### 4.3 成果引用：重新检查，不永久复制旧证据

收藏是当前项目与已有答案之间的引用关系。保存和读取均检查所属范围；不得凭其他项目的答案编号收藏或读取。`GET /api/v1/mobile/workbench/artifacts` 只返回编号、标题、时间等目录元数据及历史回答是否存在，不加载整架成果正文，也不宣称目录项的依据已经核验。点击“审阅”后，通过单条 `GET /api/v1/mobile/workbench/artifact` 才读取回答并重新校验出处；不把旧 UI 缓存当成当前授权结果。

收藏记录只保存答案编号、标题与时间，不另存答案或来源正文。详情读取时从会话历史定位该回答并重新校验来源；原回答不存在时返回不可用，不生成替代答案。当前每个项目最多 100 个收藏、单 worker 最多 1,000 个；标题最多 120 字符，项目要求记录最多 100 组。邀请网关的工作台写入有独立的每日 200 次限制，不扣问答次数，但仍受原网关并发保护。它们是当前实现的容量边界，不是生产容量承诺。

任一来源被撤回，或来源元数据无法确认完整时，收藏详情返回 `available=false`、`answer=null`，不返回原答案正文，也不在警告旁继续展示旧全文。新增收藏同样拒绝这类无法确认依据的答案。目录可以保留引用和标题，用户仍可移除收藏；它不能绕过撤回检查，也不使已撤回记忆或无法访问的答案复活。取消收藏与删除原回答、资料、记忆是不同操作。

### 4.4 状态机：展示观测结果，不假装自主执行

工作台沿用已有请求编号与回执。断线或页面刷新后优先读取状态；结果未知不能推断为“没有调用模型”，也不能自动提交第二次付费请求。请求去重不等于所有外部工具天然幂等。

单次回执说明一次请求的接受与完成；新增持久任务另有逐步骤检查点和依赖状态。解析队列、辅助调度和生成请求的边界不相同；前台等待超时也不等于已经强制停止后台计算。任何状态都不能显示为“已完成逐条事实核验”等未执行的工作。

### 4.5 持续研究：保存进度，不承诺无人值守

用户编辑目标、约束、问题与明确资料范围，批准本轮有限尝试；创建、查看、编辑和本地报告组装不调用模型。原子步骤领取与版本检查防止重复推进，未知付费结果只对账；暂停阻止后续派发，不能保证撤销在途供应商调用。资料哈希变化使相关问题及实际依赖的下游失效，不把 inventory 的调度边误当所有问题的语义依赖。

前步分析以有界材料交接而不是事实提升：共用 2,000 UTF-8 字节，完整回答放不下时只选连续完整单元，并明示节选覆盖；依赖不可用或连最小单元都无法保留时停止，不假装完成承接。报告保存引用版本，打开时重新核对来源，本地组装不增加模型调用。详细状态、次数预扣、失败重试边界及多材料科研验收见 [持续研究任务](LONG_PROJECT_RUNTIME.md)。

## 5. 尚未实施的能力

| 规划项 | 需要先解决的前提 |
|---|---|
| 浏览器控制、任意脚本和连接器 | 工具能力注册、逐项授权、数据外发边界、执行沙箱与审计 |
| 自主规划、多天无人值守、定时与事件触发 | 当前仅用户批准的有限研究 DAG；仍需额外权限、副作用幂等、长期运行策略与真实费用验收 |
| 可安装技能市场 | 来源验证、可执行代码审查、权限说明、版本与卸载机制 |

| 自动整理后提出记忆或流程更新 | 候选与事实分离、变更预览、明确确认与完整回滚 |
| 受控自改进 | 冻结候选版本与留出集，真实质量/成本对照，人工采纳和回滚 |

这些是后续设计，不是隐藏在现有按钮后面的已实现功能。不将任意自动化、多 Agent 数量或知识图谱节点增长当作 RSI 的证据。

## 6. 验收：交互闭环与答案质量分开

本轮工作台至少需要以下行为检查：

- 项目要求保存后可读取，陈旧版本不能覆盖新版本；切换项目不串内容。
- 删除后重新建立同编号项目，不会读出旧简报和收藏；清理失败不允许继续删除。
- 任务配方只改草稿，不自动发送，不额外调用模型，不扩大开关与权限。
- 相同答案收藏不重复；其他项目答案不能收藏；任一来源撤回或元数据缺失时，详情不返回原答案正文。
- 取消收藏不删除资料；收藏不自动创建记忆；已有确认记忆仍需要显式操作。
- API 失败、退出账号和页面切换后，不出现错误的成功状态或上一项目的迟到数据。
- 成果能回到真实答案与来源；未开放能力、离线演示和真实后端有明确区分。

### 本地验收入口

在已安装项目测试依赖、已构建 `clients/mobile/dist/build/h5` 的环境中，可运行：

```bash
PYTHON_DOTENV_DISABLED=1 python tests/manual_research_runtime_check.py --workbench-only
```

该脚本创建临时邀请网关、独立用户 worker 和本机假模型，检查工作台持久化、隔离与撤回；不调用真实模型供应商。追加 `--serve` 可在检查完成后保留临时回环地址用于浏览器交互验收，停止脚本后清理临时环境。这是可复跑的验收方法，不表示本文已报告该命令通过，也不是公网部署或真实模型质量评测。

这些检查通过只能证明工作台的交互和状态契约，不能证明回答更准确。**截至 2026-10-11 的双模型开发集小样本仍未通过联合质量门禁；软件交互改进不改变该结论。**后续质量验收必须继续使用新文档、实际任务、关键证据与无依据主张指标，并计入真实 token、延迟、失败和评审成本。[真实研究设计与结果](RESEARCH_GROUNDED_DESIGN.md)

本轮不承诺无限记忆、端到端加密、生产容量、已实现 RSI 或与竞品相同的市场表现。长期产品价值应由“过一周回来，仍能找到依据、纠正旧结论并继续完成任务”验证，而不是首页宣传语验证。

### 2026-10-10 本轮验收结果

- 后端相关回归：1,747 通过、3 跳过，覆盖 research、mobile、workbench、invite、请求回执与会话编号；不是仓库全部测试。
- 移动客户端：434 通过；H5 与微信测试包编译通过。编译不等于微信上传、审核或正式发布。
- `manual_research_runtime_check --workbench-only`：真实双 worker 与邀请网关联调通过。测试了用户/项目隔离、陈旧版本拒绝、服务重启、引用式收藏、撤回后关闭详情和幂等取消收藏。只有 3 次本机模拟回答调用，工作台操作不增加调用；没有使用真实模型密钥。
- 实际浏览器验证：保存后重新登录可读简报；折叠保留未保存编辑；编辑后显示未保存状态；任务配方保留已有草稿并等待追加/替换选择；切换项目不串简报；收藏后按需打开回答和 PDF 页码/原文节选。

本轮没有重新开展真实 Step 5 质量评测，没有发布服务或提交 GitHub。上述验收只支持工作台的交互、安全与状态契约，不改变 V6 未通过质量放行的结果。

## 视觉与品牌

- 暖白 `#F6F5F0`、深墨 `#1C2723`、电光绿 `#D6FA75` 少量强调，统一为 `--dt-*` 设计变量；保留现有品牌资产，不增加第三方字体或图片请求。
- 首屏面向用户自己的任务：添加资料、写出想核对的判断或问题，再沿现有问答流程查看依据。不把固定论文问答或预先整理的结论作为默认产品优势。未连接时明确引导配置真实服务，不用示例回答冒充处理了用户材料；普通聊天和可编辑起点仍保留，点击起点不会自动提交。
- 默认标识「证据之窗」：D 的轮廓像文档窗口，内部线段连接来源节点。标识与五个导航图标使用可编辑 SVG、本地生成的 PNG，不依赖第三方图片请求。
- 六个 Logo 方向保存在 `clients/mobile/public/brand/index.html`。比较页选择只切换展示，不悄悄修改应用品牌；当前默认方案仍可由项目拥有者替换，未做商标注册可用性调查。
- PNG 提供原生平台各尺寸和独立 maskable 安全区版。原生启动图标不透明、未预圆角，交给系统处理外形。

## 交互与可信度

1. 演示提示始终可见，不用装饰掩盖“未调用真实模型”。
2. 上传卡不把已接收当成解析完成；失败、未知状态明确展示。启用研究服务时，可查看原文、确认后重试或移除资料；旧资料接口仍需在桌面管理。
3. 图谱展示所选节点的真实邻接记录和来源，不把实体原文自动当作每一条边的证据，也不把无向关联画成因果箭头。补充关联明确待核验。
4. 录音/转写/发送/朗读是分开的操作。长转写保留全文、明确超限；自动停录会显示停止状态；切页停止采集和播放。
5. 手机安装入口说明 PWA 与原生 App 的差异。PWA 只缓存构建静态界面，不缓存真实问答、鉴权、上传或语音，不自动刷新草稿。
6. 记忆独立成页，仅展示当前会话的已保存摘要、来源问题和待核对标签；搜索只筛选已加载条目，不额外调用 LLM。不提供尚未打通删除链路的“彻底忘记”按钮。
7. 微信端顶部避让状态栏和胶囊；选择聊天文件或相册图片前检查平台隐私授权，发送前再次确认目标服务。拒绝授权、切页或修改服务后不继续新的上传。详见[微信测试版](WECHAT_MINIPROGRAM.md)。

## 首次体验：用自己的材料，核对自己的判断

首次入口不预设用户研究什么，也不要求先看一段固定论文演示。目标是让用户从自己的材料和问题开始：添加一段文字或文件 → 写出想核对的判断或问题 → 在现有问答中查看回答和实际返回的依据。此流程只是缩短已有功能的操作路径，不增加第二套模型、检索或判断真伪流程。

- 未连接真实服务时，使用指南的主操作是“连接真实服务”，次操作是“查看功能入口”。跳转设置不会自动保存配置或切换模式；连接、邀请登录、会话与研究权限仍按现有规则检查，不能因打开首页入口而绕过。
- H5 可从首页粘贴材料并整理为 TXT，上传前显式确认目标服务，再走现有资料上传接口。微信私人连接沿用文件选择与隐私确认；App 研究文件上传本版仍需使用浏览器，不宣称三端粘贴均可用。未连接、没有会话或未开放研究服务时，显示下一步而不是产生模拟上传结果。
- 用户自己填写待核对的问题，材料上传不等于已经提问；上传成功也不等于解析完成。资料的就绪、失败与未知状态继续由现有资料页展示，后续问题沿用当前会话的问答与引用流程，不自动发送或保存为长期记忆。
- “看依据”展示服务实际返回且可读取的来源，不承诺每个判断都能找到支持；缺少原文、资料尚未就绪或服务未开放时明确提示。材料送入上下文不代表已证明结论正确，也不自动限制问题只查询刚上传的那一份资料。
- 普通聊天仍然可用；材料入口不代替提问输入框，不覆盖未发送的问题，不把类比、演绎、归纳变成必须选择的聊天模式。后台辅助组织材料与用户查看依据沿用原有流程。

`/#/pages/studio/index` 保留为可选交互说明，不是默认首屏任务。其内容是根据 [RAG](https://arxiv.org/abs/2005.11401v4) 与 [Lost in the Middle](https://arxiv.org/abs/2307.03172v3) 摘要预先整理的固定样例，短原文、编者解读和综合判断分开；没有运行模型或处理用户资料。样例“留住这一步”只保存样例 ID、版本、来源/步骤 ID 和时间，30 天有效，不是账户长期记忆；它不能证明真实算法质量、长期记忆能力或产品优势。

验收应覆盖用户材料从输入、明确授权、上传、解析到回答来源的真实链路，并单独测试遗漏证据、错误引用和无依据判断。首页入口与模板测试不能替代真实模型效果、客户可用性或正式上线验收；不承诺固定几十秒得出结论，也不据此宣称回答质量已经提高。

2026-10-11 实现验收：移动客户端 **730 项测试通过**，H5/PWA、微信 guest 与 App 资源构建通过（微信主包 523,315 字节；App 资源不是签名安装包）。隔离本机网关中，使用新输入的人工构造原文走通上传、排队、真实解析、就绪、用户自拟问题及展开原文依据；模型由明确标注的本机假服务替代，没有调用真实模型。这验证功能链路，不验证回答质量提升或生产可用性。粘贴原文仅暂存页面内存，不进入本地持久化；同会话页面切换保留，刷新不保证保留。截图位于本机 `dist/evidence-entry-20261011/`。

## 2026-10-10 交互与视觉升级

- 基础内容宽度 760 px，助手桌面工作台 1080 px、核心阅读/输入区 820 px；手机维持单列。欢迎图形由 CSS 表达“问题 → 依据 → 下一步”，只是装饰，不是假装生成了知识图谱或任务状态。桌面紧凑欢迎区，避免发送按钮被底部导航遮挡。
- 设置页分为“开始、连接/账号、回答、隐私”四个手动分区，保留未保存修改与显式保存。分区有 pressed 状态、键盘 Enter/Space 操作；切换本身不检查连接或调用模型。
- 已有提问草稿时，快捷起点先显示“追加、替换、保留”选择；完整文字保留，超限只能编辑后发送。未解决回执、录音、处理中不能被快捷卡绕过，离开页面不会恢复过期选择。
- 图谱点选节点后展开并滚到原文/关系详情；晚回调不能把用户拉回旧会话。资料可提问时增加返回助手入口，只切换当前会话，不自动提问，也不声明仅查询某一份文件。
- 关键说明加深颜色、提高字号；主要操作区至少 44 px，保留焦点提示、减弱动效与微信可选择文字分支。手机浏览器尺寸检查不替代屏幕阅读器或真机验收。

## 验收边界

### 2026-10-11 图谱语音定位与思路回溯

目标不是多一个聊天输入框，而是降低“我在看什么、为什么来到这里、怎么回去”的记忆负担。语音只负责把意图带入可编辑的定位栏，确认后驱动图谱视图；手势/鼠标/触屏负责直接操作，后台材料组织负责补充理解，三者不混为一个推理模式。

- 轻量图谱增加“找到某实体”“A 和 B 有什么联系”“回到上一步”“看原文”的定位入口，语音与文字共用。已有定位文字时，转写需要显式选择替换或保留；不自动查找、不自动提问、不截断转写。超过 256 字符须缩短后再执行。
- 本地名称匹配精确优先，模糊名称和重名必须选候选；描述中碰巧出现一个名称不能触发精确定位。关系查找使用有预算的两轮广度优先搜索，先原始边、再允许补充边，只展示一条不超过 3 跳的现有无向路径。最多扫描 2,000 节点/8,000 边，遍历共享 256 节点/2,048 边检查预算，候选最多 8 项。预算或摘要限制导致未找到时不宣称关系不存在。
- “这次思路”保留本次定位问题、当前位置和最近 12 步页面历史；点击路径节点才读取该实体原文，不批量预取、不调用问答模型、不生成新边。原文区提供回看问题与联系入口，重复定位同一位置不重复读取原文或填满历史。
- 路径不是因果证明；补充边、补充节点和截短的关系说明分别标注。实体片段不能冒充每条边的证据。页面历史也不冒充图谱关系链，切会话、刷新或离开页面即清空，不写入长期记忆。
- 示例的三种方法改称“检查条件 / 比较案例 / 借鉴思路”，明确是材料组织示例，不是聊天模式；后台整理的前提和条件标为“待核对”，只有实际经过逐字匹配的引用才保留相应原文标签。后端算法与辅助开关未改变。

最终客户端 **633 项测试通过**；H5/PWA、微信 guest、App 资源编译通过（微信主包 515,768 字节，App 资源不是签名安装包）。浏览器用演示数据验证语音到定位草稿、显式执行、关系路线、节点原文、返回及输入框值同步，检查 390/1440 px 布局；截图在 `dist/graph-context-20261011/`。没有调用真实麦克风或模型，语音组件三平台测试使用模拟设备与网络。这里只支持明确的常见定位表达，不是任意自然语言理解；邀请版仍未开放图谱和语音，旧 Flask 标准/沉浸图谱本轮未接入该定位栏。真实语音识别、真机和客户注意力/任务效率改善仍需另外测评。

### 2026-10-11 语音作为草稿入口，手势作为操作辅助

- 语音与打字共用提问草稿和后续问答流程，不设独立“语音推理模式”。界面区分准备、录音、停止待转写、转写和检查草稿；只在用户点击发送后提问。转写追加到已有文字之后，保留全文，并沿用字符数与研究服务 UTF-8 字节预算。
- “撤回这次转写”仅恢复本次追加前的草稿；用户继续修改后不再提供该操作，避免覆盖新编辑。撤回时同步重建输入框，修复 uni-app H5 聚焦输入框可能保留旧显示值的问题。操作按钮支持 Enter/Space，并避开输入法、重复按键和组合快捷键。
- 转写、朗读排队等待时，取消、切页或连接身份变化会在真正发送前再次检查；已发出的服务端处理不能承诺撤回，只丢弃过期结果、不自动重试。麦克风授权迟到且连接已变化时立即释放媒体流。当前朗读即使遇到其他忙碌操作也能停止。
- 图谱的鼠标、触屏、滚轮与图谱快捷键优先于摄像头手势；暂停后需要用户手动恢复。丢失指针捕获、窗口失焦和摄像头断帧会释放临时拖拽，不删除节点或来源。手势不调用生成模型，不产生 prompt；语音转写/朗读仍可能产生语音服务费用。

验收：移动客户端 **556 项测试通过**，H5/PWA、微信 guest 和 App 资源编译成功（微信主包 487,059 字节；App 资源不是已签名安装包）。在 390 px 浏览器中使用明确标注的演示转写验证键盘操作、追加草稿、撤回、焦点与“未自动提问”，没有调用真实麦克风、ASR、TTS 或问答模型。截图保存在 `dist/input-interactions-20261011/voice-draft.jpg`。邀请内测仍未开放语音；移动客户端轻量图谱没有新增摄像头手势入口，手势改进针对桌面 Web 的标准/沉浸图谱。真实录音识别率、摄像头误触率、手机多指与微信真机仍需单独验收。

### 2026-10-11 手机与电脑分别适配

- 手机与窄窗口保留五项底部导航和单列阅读；H5 宽度达到 1100 px 时切换为 208 px 左侧导航。侧栏使用原生按钮，支持 Tab、Enter、Space 与当前页提示；隐藏页面、登录和独立交互样例不会残留侧栏。没有 `:has()` 支持的旧浏览器沿用底部导航，不让侧栏覆盖内容。
- 研究资料页在宽屏显示“资料目录 + 原文阅读区”，右侧独立滚动；手机按点击定位到原文，关闭后回到选中的资料。预览、完整片段和返回分开；只有明确打开文档/来源才请求正文，返回已有预览不重复获取，不批量预取资料。
- 手机输入字号为 16 px；长回答离开输入区时可点“回到输入框”，只定位和聚焦，不发送问题。按钮用 `IntersectionObserver` 判断可见区，并预留底部导航遮挡；切页即停止观察，拒绝旧回调，不增加滚动轮询、网络或模型请求。
- 本轮没有改模型、后台推理算法或研究辅助开关，也没有放宽隐私与鉴权边界。

浏览器验收覆盖 320、390、768、1099、1100、1440 px 的聊天布局，检查整页无横向溢出、导航断点与输入字号；通过隔离本机网关和人工构造资料检查桌面双栏、手机原文定位、返回与关闭流程。资料阅读按钮也支持 Enter/Space，不让重复按键、组合快捷键或中文输入法状态触发读取。最终移动客户端 **513 项测试通过**，H5/PWA 与微信 guest 构建通过（微信主包 482,081 字节）。布局截图保存在本机 `dist/adaptive-ui-20261011/`。这不是安卓/iPhone 软键盘、微信真机、屏幕阅读器或真实模型效果验收。

### 2026-10-11 软件与交互收敛

- 助手以输入为主：简化欢迎区与模式提示，快捷起草、项目简报和成果收藏默认收进“项目工具”。不会因展开工具自动发送问题。
- 回答与收藏正文使用安全的 Markdown 子集展示标题、列表、引用、代码及可横滑表格。原始回答仍用于复制与出处核对；HTML、图片和外链不执行、不加载、不自动跳转。过长或复杂的内容完整回退纯文本，不截断。
- 切会话或新建会话前确认未发送草稿和未保存简报。同项目切换资料/设置页时，未保存简报仅留在页面内存；返回后重新核对权限与版本，服务端已有更新时阻止直接覆盖。刷新浏览器、卸载页面或更换身份/项目不会保留这份未保存副本。
- 输入框支持 Ctrl / ⌘ + Enter 发送，普通 Enter 换行；中文输入法选字、重复按键及忙碌状态不能误发。发送被阻止时给出下一步提示。
- 研究资料页显示真实排队/解析/就绪/失败状态，提供有次数与时间上限的只读状态更新、名称搜索及状态筛选。不会自动重试解析、伪造进度或调用模型；查看原文后定位到阅读区，就绪资料可返回助手继续提问。

# DocThinker 邀请内测部署包

把网页、邀请登录、固定用户后台封装为一套 Docker Compose 服务。朋友使用网页，不需要安装 Python、Docker 或填写模型密钥；只有部署者需要配置服务器。

**默认交付范围是聊天与历史，最多五人。** 可通过下面的显式开关启用研究核心：受控论文导入、原文检索/引用和用户确认的项目记忆。图谱增长、自进化、语音及团队共享仍不开放。洞见页面仍是本地构造样例，不是线上算法效果证明。

这是一份可构建的源码部署包，不是预先构建的容器镜像，也没有自动创建公网网址。需要 Linux 容器环境与 Docker Compose v2；macOS 可使用 Docker Desktop。构建阶段需从官方镜像仓库、PyPI 和 npm 下载依赖。

**包内与完整工作区的区别：**按本页的 `deploy/invite/manage.py`、`preflight.py` 和服务自检操作。根 README 的全仓库安装、`tests/manual_*`、开发回归及未列入 `PACKAGE-MANIFEST.json` 的历史评测链接，需要完整工作区；不要在 ZIP 内直接运行这些命令。指定新论文 fixture、计划、结果摘要和配对 runner 随包提供，但原 PDF、原始答案、账号及密钥不分发；复跑须另行下载核对公开论文和明确提供受保护凭据，不会自动调用模型。可选语音／图谱设置文档只供了解完整项目，不意味着邀请版本已开放它们。

## 第一次启动

先在完整工作区或可信来源取得的代码目录运行只读包校验，再解压：

```sh
python3 deploy/invite/pack.py --verify /绝对路径/docthinker-invite-source.zip
```

它检查 ZIP 路径、重复项、构建清单、逐文件 SHA256 与 CRC，不解压、不执行包内代码，也不读取账号或模型设置。必须同时核对交付者提供的整个 ZIP 的 SHA256；包内清单只证明内部一致，不能证明发布者身份。校验通过不代表容器构建、实际 HTTPS、手机或真实回答质量已通过。

解压 ZIP 后进入 `docthinker-invite` 目录。运行以下命令（也可在原项目根目录运行）：

```sh
python3 deploy/invite/manage.py setup
python3 deploy/invite/manage.py build
python3 deploy/invite/manage.py init
python3 deploy/invite/manage.py add-user --username alice --port 8101
python3 deploy/invite/manage.py up
```

`setup` 只询问一次网站地址、模型 API Base URL、模型标识和密钥，密钥隐藏输入。网站默认 `http://127.0.0.1:8088`，适合本机验收；给朋友使用时应填最终同源 HTTPS 地址，不带路径。

必须先确认模型服务允许这种多人应用用途，才输入 `I_HAVE_PERMISSION_TO_SHARE`。不确认也能保存配置并准备账号，但启动被阻止；程序不会替你取得厂商授权，不能把个人套餐自动当作可转供服务。

创建用户时会输出一次性邀请码，**私下转交用户名和邀请码**；不要将它们放进网址、二维码或 Git。试用者进入登录页，用邀请码设置自己的密码。每位用户用不同的固定端口：8101–8105，worker 端口只在容器回环内监听，不对外发布。

`up` 先做离线配置检查，再等待网关及全部用户后台健康；启动和健康检查不调用模型。真实问答只有在用户点击发送时触发。失败不会自动换成演示回答，也不会无限自动重启。

## 开启研究核心

默认不自动扩大账号权限。为新的研究试用账号授权上传，并在每次启动时显式选择研究模式：

```sh
python3 deploy/invite/manage.py add-user --username researcher --port 8102 --research-uploads
python3 deploy/invite/manage.py check --research
python3 deploy/invite/manage.py up --research
```

已有实例须先 `down`，再 `up --research`；数据卷保留。`--research` 不写入永久设置，不带此参数的下次启动仍为聊天模式。带上传权限的账号在默认聊天模式下会被配置检查拒绝，不能意外启动旧上传路径。账号权限创建后不能靠前端改动取得；现有账号尚无在线升级界面，使用新预留账号，不删除旧账号资料。

试用者登录后，在助手建立研究项目，到资料页导入 PDF/TXT/MD（单文件 10 MiB，每项目 20 份）。同一论文可独立加入两个项目；同项目重复导入返回既有文档。解析是本地持久作业，重启可恢复；不做 OCR、不调用模型。未开放上传的账号只能使用自身已有资料，不可上传。

用户直接正常聊天或写作，不需要选择推理模式。基础检索最多选 8 条原文节选；启用 Insight 且匹配知识包时可再补最多 2 条，所有原文仍共用 12,000 UTF-8 字节上限，不替换基础证据。无匹配原文时说明缺口。后台按任务最多选一种类比、演绎或归纳，补充最多 3 项/4,000 字节的完整论证线索，不能挤掉已有原文；模型把这些作为参考，不把推测说成原文事实。逐主张出处可定位连续原句，并提示数值、否定和条件差异；改写仍需人工核对。正常生成最多一次模型调用，后台算法不调用模型；旧 `evidence` API 保留零模型逐字摘录兼容。关系解析只支持短中文/英文关系和明确规则，缺少完整前提或超过证明预算时不强行输出结论。

预算装配复用一次检索排序，按完整信息块取舍；模型消息最多 24,576 UTF-8 字节。普通聊天最多 2,048 输出 tokens，有实际原文入模的研究回答最多 8,192；上限可能同时包含模型推理与正文，不是承诺生成相同长度的报告，也不是账单金额上限。这是模型无关的任务预算，原文字节预算不变，不能从客户端绕过。每个研究服务的可选辅助最多一个已提交/运行任务、无等待队列，前台最多等 1 秒；忙、失败或超时则照常使用原文回答。超时不能杀死 Python 线程，任务槽要等真实结束才释放，防止后续请求不断叠线程；不自动重跑或补一次模型。

### Harness 与洞见辅助的部署验收

源码包与 Docker 构建上下文均包含五个知识包的 `knowledge.json` / `SKILL.md`、Harness 和 Insight Runtime。构建时会验证所有知识包可以加载；只有 Python 模块可导入不算资源齐全。普通查询与邀请查询复用同一运行入口；运行回执仍是进程内阶段记录，不代表具备长期任务断点续跑。

部署默认关闭可选上下文补充检索。要在研究内测中验证这一能力，由部署者显式启用：

```sh
DOCTHINKER_RESEARCH_CONTEXT_ASSIST=true python3 deploy/invite/manage.py up --research
```

如需按无本地语义模型的验收条件运行，可在同一命令前另设 `DOCTHINKER_RESEARCH_SEMANTIC=off`。该变量经管理器、Compose 和 worker 传递，仅接受 `auto`（默认）、`off` 或 `local`；关闭语义检索会使用词面检索，不能把它当作相同检索质量的替代。

该设置经管理器、Compose 和 worker 白名单转发，不会新增供应商模型调用。API 的 `insight_mode` 支持 `auto` / `off`，可独立于 `knowledge_skill_mode` 对照动态辅助与静态方法卡；邀请网关会原样转发。不同模式应使用不同 `request_id`，复用 ID 更改模式会返回冲突，避免误把旧答案当成新评测结果。代码测试与 SHA256 清单校验不证明真实回答质量，模型实测与手机访问仍须在目标部署完成后验收。

解析与问答分离：所有邀请 worker 共用一个解析子进程槽，同事件循环最多 4 个等待者、按 FIFO 取得本地顺序，排队与跨进程锁等待合计最多 120 秒，解析本身另有 25 秒上限。跨进程依靠 `flock` 互斥，不承诺严格 FIFO；等待不阻塞事件循环，超时显示解析容量不可用，不自动重交。取消已启动的解析时，先回收子进程再释放槽。

记忆页保存用户确认的偏好、项目决定/结论，支持搜索、修订、有效期、历史、归档/恢复及删除。FTS5 检索完整保留期，单次仍只选有限候选；归档后相关问题仍可召回并标注归档状态。`as_of` 是 UTC Unix 秒，表示按现在已知修订查询某个事件时点；它不模拟当时系统的完整知识。上传、检索、记忆管理、算法推理、导出与状态查询不调用模型。

删除文档会撤销原文预览/未来引用，并使依赖记忆及证明失效；查询过去时间也不能恢复已撤回的依据。旧普通聊天、外部模型记录、剪贴板或备份不会自动擦除。项目导出包含当前资料清单与有效确认记忆（包括归档项），超过导出预算会明确失败，不静默截掉后半部分；不是完整聊天/论文导出。此模式没有自动偏好学习、夜间自进化或无人批准的自主长期任务。详见 [实际核心架构](../../docs/ARCHITECTURE.md#有界研究核心2026-10-10)。

### 用户批准的持续研究任务

开启研究核心后，聊天页面的「长任务」可保存你的真实目标、约束和 1–6 个分析问题，指定每步资料范围及前序依赖。先保存计划，再明确批准本批最多 1–6 次模型调用；默认不会在开机、页面打开或资料变化时自动请求模型。计划元数据、资料核对、状态读取和有版本的报告汇集不请求模型。

每一步的请求身份、资料快照与产物引用持久保存。预算用完可暂停，重启后先读取状态，再批准继续；已完成步骤不自动重问。已知失败需明确重建待办并另行批准；结果未知先对账，不自动重试。修改问题或材料使受影响步骤及其下游失效，不重做所有无关工作。前步骤只作为有界、标记完整或节选的分析线索；当前原文才是事实依据，依赖不在批准范围或完整单位无法装入预算就停止。

网关按批准的最大次数**预扣每日问答额度，未使用不退**；不是金额上限，供应商仍按实际请求计费。每个分析步骤至多一次生成，当前输入总量受 24 KiB UTF-8 字节限制，有资料时输出上限 8192 tokens；字节不等同于模型计费 tokens。任务库另有 64 MiB、每用户 100 个任务、每项目 20 个任务及每步 32 个产物版本的有限容量。需要新增/删除问题或改变依赖拓扑时新建计划，本版只在原拓扑内修订。

报告按当前有效来源重新解析已有回答引用，显示文件、页码或无页码声明、片段定位与交接覆盖情况；不额外请求模型润色，**不保证已经形成完整综合论证或语义正确**。源撤回时相关报告不显示旧正文；已经复制/下载的本地副本无法同步撤回。完整机制和在完整工作区执行的验收命令见 [持续研究任务](../../docs/LONG_PROJECT_RUNTIME.md)。这不是任意工具执行器或递归自我改进证明。

### 扩展记忆与请求记录容量

每个 worker 默认研究 SQLite 配额 512 MiB、请求回执 SQLite 配额 256 MiB；所有邀请用户共用的网关注册库另有 64 MiB 新请求准入配额。上传原文件另受现有文档配额限制。已经取消 100/500 条记忆、5,000 次修订和 10,000 次请求的终身数量门槛，但磁盘、索引与备份仍需要真实容量。容量用尽会明确拒绝新请求，不删除旧记忆或去重凭据；网关拒绝新增请求不会扣减当天次数。

部署者可提高字节配额后重启；例如研究库 1 GiB、回执库 512 MiB、网关注册库 128 MiB：

```sh
python3 deploy/invite/manage.py down
DOCTHINKER_RESEARCH_STORAGE_BYTES=1073741824 DOCTHINKER_REQUEST_JOURNAL_BYTES=536870912 DOCTHINKER_INVITE_REGISTRY_BYTES=134217728 python3 deploy/invite/manage.py up --research
```

这三个设置经过 `manage.py → Compose → worker / gateway` 白名单验证，仅接受 65,536 至 1,125,899,906,842,624 的整数字节数；实际需要给索引和数据库结构留空间，极小配额可能无法写入。设置不自动持久化，后续启动应继续传入相同值；不会从 `.env` 自动载入。扩容只改变准入配额，不预分配物理磁盘，也不改变单次上下文、上传数量或问答日配额。原始用户数据卷保持不变。

网关按整个注册库的 SQLite 活跃页（包括索引和计次记录）判断新请求准入，空闲页可复用。它不是文件系统硬配额：数据库空闲页、事务日志、备份及登录/管理记录另需磁盘空间。已接受的请求 ID 和内容指纹永久保留；即使下调容量或容量已满，同内容旧请求也不会重新计费，不同内容复用旧 ID 仍会被拒绝。容量按实例共享，不是每位用户的额外问答额度。

请求回执保留已接受 ID/内容指纹。缓存回答超过七天或缓存预算时只清除可回放内容，旧请求仍不能重复执行；无法确认结果时显示“结果未知”。已收到模型响应但截断、空正文或格式错误的请求显示明确失败，固定失败码重启后仍保留。同一 ID 的重发或状态查询不会再次调用模型。界面保留草稿，只有用户明确返回草稿才解锁新提问；失败不代表供应商未收费。增加存储不会使旧请求重新调用模型。

## 日常管理

```sh
python3 deploy/invite/manage.py status
python3 deploy/invite/manage.py check
python3 deploy/invite/manage.py revoke-user --username alice
python3 deploy/invite/manage.py down
```

`down` 保留账号与聊天数据，不带 `--volumes`。新增用户后需显式 `down` 再 `up`，使固定 worker 列表生效。撤销后网关拒绝该账号继续认证和请求；这不等于删除历史资料，也不能撤回已经发送给模型的内容。

如果**尚未注册**的试用者错过默认 48 小时有效期，或遗失邀请码，管理员可重发，不必占用新账号/端口：

```sh
python3 deploy/invite/manage.py reissue-invite --username alice --expires-hours 48
```

仅 `pending` 账号可用，有效期可设 1–168 小时，默认 48 小时。新码与到期时间仅在管理员本次输出中提供，请私下转交；旧码立即失效。每次成功执行都会再次替换前一码，**不是幂等查询，也不会自动重试**；若输出丢失，明确再执行一次即可生成另一新码。SQLite 事务把换码与并发注册串行处理：注册先完成则拒绝换码，换码先完成则旧码不能注册。此操作保持用户 ID、worker、权限、端口及资料不变，不需为换码重启现有 worker；已注册、已撤销或不存在的账号统一拒绝。它不是密码重置、恢复撤销、回收固定端口或删除账号功能，没有公网管理接口。

`status` 与 `down` 不需要读取配置或模型密钥：即使配置遗失、密钥权限损坏或轮换未完成，也可检查/停止固定的 `docthinker-invite` 项目。两条命令仍需要可用的 Docker/Compose，不会启动容器、写入密钥、选择其它项目或删除数据卷；`up`、`check` 及 Compose 内的 `init/add-user/reissue-invite/revoke-user` 仍执行完整配置检查。下述本机冷导出/清理使用单独离线入口，不读模型配置。可选 HTTPS 边缘由运营者单独管理，这不声称已关闭它的公开端口。

配置默认保存在项目外的 `~/.local/share/docthinker-deployment/`。可用 `--config-dir /绝对私有目录` 指定新位置；已有文件不会覆盖。设置 JSON 不含密钥，源密钥权限为 0600。为兼容容器 UID，助手在同一个 0700 私有目录生成 0444 只读容器副本，通过单文件 Docker secret 挂载。不要放宽父目录权限或把副本复制到公共目录。Docker 管理员及本机同一账号仍可读取密钥，Docker secrets 不是密钥保险箱。[Docker secrets 说明](https://docs.docker.com/compose/how-tos/use-secrets/)

账号与数据位于固定 Compose 项目 `docthinker-invite` 的 `invite-data` 命名卷。不要运行 `docker compose down -v`，也不要把生产卷挂进其它实验实例。备份应包含卷和受保护配置，并制定用户资料保留/删除规则。

### 单账号私有导出与资料清理

本版新增管理员离线命令，只操作**明确指定的本机私有注册数据目录**；不会猜测、导出或删除 Docker 命名卷。先撤销账号，再正常停止整个 runtime；仍运行的 supervisor 或目标 worker 会阻止操作。以下目录均为示例，不能直接照抄成实际路径：

```sh
python3 deploy/invite/manage.py export-account --data-dir /srv/private/docthinker-registry --username alice --confirm-username alice --output /srv/private/exports/alice.zip
python3 deploy/invite/manage.py purge-account --data-dir /srv/private/docthinker-registry --username alice --confirm-username alice
```

这两条命令不读取模型设置或密钥，不增加公网管理路由。私有数据目录和输出目录须由当前 OS 用户拥有，权限 `0700`；新 ZIP 为 `0600`，不能覆盖旧文件。命令要求再次明确确认规范化后的用户名；**第二条会删除资料，请先完成并核验所需导出。**

仅支持本版新建的 lifecycle-protocol-1 账号。目标 worker 自己持有生命周期锁，supervisor 异常退出也不能把仍运行的 worker 当作已停机；旧协议账号不会自动获得新标记，也不能靠端口空闲推断安全停机。旧账号的迁移和目标 Docker 卷维护仍需另行设计与验收。

导出保留该账号当前业务文件与原始上传资料，包括 `data/` 和 `_system/research/`；不复制注册库、供应商/worker 凭据或 `runtime/home/cache/tmp`。用户自己写在聊天和文档里的秘密仍属于导出的用户资料，工具不会自动识别并去除。它不是公开分享链接或加密保险箱。

资料清理删除该账号 live worker 目录及注册凭据、配额、请求记录；保留用户名、账号 ID、占用端口和 revoked/lifecycle 状态，防止旧身份或端口复用。中途失败返回“未完成”，账号继续撤销，修复本地存储问题后可用同一确认重跑；已完成的清理拒绝重复执行。**不是全身份抹除、物理安全擦除，也不删除备份、已下载副本或供应商记录。** 本机合成账号测试不能替代实际容器卷、保留政策和恢复演练。

### 离线备份与恢复自测

```sh
python3 deploy/invite/manage.py backup-self-test
```

这条命令只在临时目录生成模拟 SQLite、原文和空目录，真实执行备份、SHA256/SQLite 检查、恢复、篡改拒绝及禁止覆盖测试，完成后删除临时数据。不读实际配置、密钥或用户资料，不调用 Docker/模型，也不会自动将发布门禁的 `backup_restore` 标为已验收。

对于已经停止服务、workers **及全部管理写入**的本地数据目录，可执行以下命令；示例路径需替换为自己管理的实际目录：

```sh
python3 deploy/invite/manage.py backup --data-dir /srv/docthinker-data --output /srv/private-backups/before-upgrade
python3 deploy/invite/manage.py backup-verify --backup-dir /srv/private-backups/before-upgrade
python3 deploy/invite/manage.py restore --backup-dir /srv/private-backups/before-upgrade --target-dir /srv/private-restores/recovered-data
```

数据根目录、备份根目录及新目录的父目录须属于当前执行用户且权限为 `0700`；恢复目标必须不存在。备份是 `data/` + `BACKUP-MANIFEST.json` 私有目录，文件权限 `0600`，包含账号、历史、记忆和资料等私密数据，**不是加密备份**；SHA256 只检查一致性，不是数字签名。工具拒绝运行中的 worker 锁、符号/硬链接、非空 SQLite WAL/journal、额外文件、损坏数据库和超过 10 万项/50 GiB 的数据。存在未 checkpoint 的事务时必须先由运营者停机处理，工具不会自动修改原数据库。

该命令不导出 Docker 命名卷、不恢复进正在运行的实例、不携带外部配置/模型密钥，也不保证有写入时的在线一致性。当前默认部署使用 Docker 卷，因此还须在目标主机按实际 UID/卷路径完成停机导出、保密保存配置密钥、恢复到独立实例及登录/资料验收；本地自测通过不能替代这项验收。保留期限与删除用户数据时也须处理历史备份。

## 让朋友真正访问

默认只发布 `127.0.0.1:8088`，不会把电脑直接公开。需要一个实际的 HTTPS 入口：可以将这套包放到服务器，或在明确授权后接加密隧道。**打包完成不等于公网部署完成。**

提供 `compose.https.yaml` 与 `Caddyfile.container` 作为独立可选 HTTPS 边缘模板。使用前须完成域名/DNS、服务器网络、费用及相应运营要求确认，并将设置的 `origin` 与最终网址对齐；管理员手动导出非敏感的 `DOCTHINKER_DEPLOY_*` 设置和只读 secret 文件路径，再叠加两个 Compose 文件启动。普通 `manage.py up` 不会选择这个公开端口模板。

只向外开放 HTTPS 网关，不开放桌面服务、管理 API 或 worker 端口。代理不得记录请求正文、Authorization 或口令。HTTPS 在代理终止，运营者、代理和模型服务商可能接触对话；不是端到端加密。电脑/服务器停止后服务不可用。跨用户隔离、手机网络、离线提示和真实模型必须按实际部署复验后再发链接。

## 3. 可见答案的逐项来源审查

### 3.1 有真实依据的增量

两版都把跨片段连接和演化作为待验证的产品方向，而不是只追求存储量；A-MEM 的 LG / ME 消融、多跳 ROUGE-L 44.27 对 18.09、T-SNE 图注均可定位。原 p7 Table 2 的消融确实在所列各类别中完整配置较好，不把这句误判为与全模型排行榜混淆。AUTO 另正确读出 note 属性、三个模块，以及 Zep 的 episode **非有损**存储，并建议保留原记录，不全量替换为图。

两版都没有声称已经开展私人助手真人试验；AUTO 对误链 / 记忆污染明确说节选没有数据，是合理的待验证风险，不应当成论文实测结论。

### 3.2 OFF：非无损与无损不是同一含义

OFF 两处将 Zep episode 写成“非无损存储”。S4 明确是 `non-lossy data store`，原 p3 还解释双向索引可从语义内容回到源 episode。正确含义是无损 / 非有损原始保存。OFF 的中文把方向反过来了，且又用它解释原始保留成本，造成内部含义矛盾。不能因为后文提了原始数据就忽略两处明确反向表述。

AUTO 此处正确。本轮没有据此说 AUTO 整体通过：改对一个词不能抵消其他证据与实验设计问题。

### 3.3 OFF：“论文没有摘要基线”是越过节选范围的错误

OFF 开头称“两篇论文的实验基线均为其他记忆系统或检索方法，并未直接与静态摘要对照”。但 Zep 原 p6 Table 1 明列：

| DMR，gpt-4-turbo | 分数 | 来源属性 |
|---|---:|---|
| Recursive Summarization | 35.3% | † 引用 MemGPT 论文结果 |
| Conversation Summaries | 78.6% | 本文实现的 session summary 基线 |
| Full-conversation | 94.4% | 本文完整历史基线 |
| Zep | 94.8% | 本文评测 |

A-MEM p5 也将 LoCoMo 基线定义为完整先前对话直接入 prompt，ReadAgent 包含 gisting。不能把未召回的基线当成全文不存在。具体滚动摘要策略仍可能与产品设计不同，私人助手迁移仍需验证；但这个正确的谨慎结论不需要虚构“没有摘要比较”的前提。

### 3.4 两版：局部额外网络开销不等于整体响应更慢

两版都引用 S5 强调服务化记忆的网络延迟成本，该局部句本身真实。但原 Zep p7 Table 2 的整体结果是：

| LongMemEval-s | 完整历史延迟 | Zep 延迟 | 上下文量 |
|---|---:|---:|---|
| gpt-4o-mini | 31.3 s | 3.20 s | 约 115k → 1.6k tokens |
| gpt-4o | 28.9 s | 2.58 s | 约 115k → 1.6k tokens |

作者在说明额外网络开销的同时报告整体约 90% 延迟下降，两者并不矛盾。报告价值与代价时只取额外开销、漏掉上下文缩短带来的净下降，无法公平支撑“主要代价是延迟”及据此暂缓分布式图的理由。应分别讨论离线建图 / 更新、检索网络、生成上下文及实测端到端成本；私人助手产品仍需测，而不是把此论文数字直接迁移。

A-MEM S7 的“效率好”后面原 p16 还有约 1,200–2,500 对 16,900 tokens 的解释，本次截断未给。OFF 如实说“节选没有成本数值”比说全文没测谨慎，但两版都缺主要实测成本证据。这里有实质选材问题，不是仅靠更强提示就能补出原文事实。

### 3.5 消融收益被推广为不可缺少的基础设施

OFF 写两模块“必需”，AUTO 写不是可选项、是复杂推理基础设施。这些是把一种实现、固定模型和 LoCoMo 上的消融收益升级为跨场景必要条件。S2 可以支持“在该设置保留两模块更好”，不能证明其他实现、所有长期助手或每类任务必须如此。AUTO 又用结构来源 S4 支撑“两篇验证了复杂推理价值”，Zep 的具体实验则没有说清。

Zep DMR 仅 500 段、每段 5 个 session / 至多 60 条消息；作者自己强调单轮事实检索、现代模型完整上下文能处理，Zep 相比同模型完整历史只是边际提升。LongMemEval-s 约 115k tokens、包含多种任务；其 p7 Table 3 也有 single-session-assistant 下降和小模型 knowledge-update 下降。两版都没给这些边界，不能把“企业评估较贴近实际”当已证明所有复杂记忆任务优胜。

### 3.6 小实验仍不能直接按表执行

OFF 的优点是明确 B1 原始 RAG、B2 摘要、B3 轻量组织三个固定方向；有相同模型参数、100 问、P50/P95 及数值门槛。但它把拒答从准确率分母排除：不同系统可以因多拒答而改变分母，甚至虚高正确率；有意不可回答问题还可能需要把正确拒答计对。未规定同题配对、拒答 / 错误 / 超时等处理就不能比较。

AUTO 控制了 LLM、embedding、k，但“F1 或 ROUGE-L”、“A-MEM 或 Zep”、“真实历史或 LoCoMo 子集”没有冻结为一个实验。额外问题包括：

- 拟取 multi-hop / temporal 子集，却以 single-hop 下降 >5% 作为停止条件，没有安排相应对照题；不能凭写了停止规则就认为可测。
- 主假设对比“原文或静态摘要”，实验只给原始检索对照；无法据此判定相对摘要的主张。
- 50–100 个“历史”与不足条件中的 30 个“有效样本”不是同一明确单位，问题数和聚合方法未定；F1 的 token / answer / macro 口径也不明确。
- 用户愿不愿忍受延迟被称为关键未知，实验却只有系统 P95，没有用户偏好或可感知阈值测量；候选 200 ms 不等于已经测出用户容忍度。

两版通过 / 停止 / 不足规则仍有未覆盖区间。例如样本充足、提升 10 个百分点、延迟增加 300 ms、无单跳退化：不满足通过，也不满足正式停止或不足。AUTO 额外说“差距接近就停止”，仍没有“接近”的数值定义。OFF 最后把所有未通过直接说成收益不足，也混同了证据不足与有反证。

因此两版都有有用实验骨架，但需重新冻结一条候选路线、一个主要指标、统一分母和完整判定去向；不能把这些问题归为排版小修。方案是拟议而非已执行，报告没有将建议数值视为用户授权或论文门槛。

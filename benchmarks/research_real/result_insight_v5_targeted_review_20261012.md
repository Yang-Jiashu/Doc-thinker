# Insight V5：两题定向真实回归

2026-10-12。**四次真实请求均完整交付，形成两组有效对照；回指对象的输入修复生效，但实验设计闭合和逐主张引用仍未通过质量验收。** 旧 CuratedTrec/TriviaQA 错绑本轮未复现；OFF 正确使用了恢复的前提，AUTO 没有使用该预处理主张，不能将其算作 AUTO 正确归属的主动验证。AUTO 的假设依据更具体，但仍出现未设计的反证对照和反证方向错误；报告仍有可定位的错引和错误缺口断言。

## 范围与协议

本轮只复验 V4 暴露问题的两题：可检验假设、私人研究助手报告，使用固定版本的 RAG、Lost in the Middle、MemGPT 三篇公开论文。文献综述题没有重测。它是**已看过前轮答案的开发 AI 非盲定向回归**，不是封存测试、独立专家评价、跨模型评测或统计显著性检验，也不是整个产品的验收。

比较仍是动态 Insight **OFF / AUTO**：两臂普通后台辅助与静态知识卡都开启。两臂最终静态卡数量、来源数量可能不同，不能称作整个后台辅助开关对照，更不能将差异归因于单句提示。

本轮版本包括回指先行句保护、来源归属修复及 `grounded-answer-contract-v4`；合同增加实验操纵/对照/反证对应、缺先行对象不猜对象、后台检查不扩成交付清单等约束。V4 原始记录和报告没有改写；版本不同，不把 V4、V5 合并成同一实验。

- 实际运行：`dist/insight-deploy-smoke-v5-20261012/`。
- 冻结准备：`dist/insight-deploy-smoke-v5-prepare-20261012/`。

## 可检验假设：有所收敛，仍不能直接执行

两臂都交付了一个假设、来源观察、机制、替代解释和反证实验。OFF 更简短；AUTO 利用新增 S10 将启发具体化为 end-only 与 before-and-after query placement 的比较，并将 key-value 的原始观察与 QA 迁移假设分开。这部分有真实材料增量，不是仅靠增加提示文字。

### V4 问题的变化

- OFF 不再把“长度越长效应越强、instruction-tuned 比 base 更强”写成主假设必须同时验证的调节预测，缩小了目标。
- AUTO 的主实验已明确列出 **query only at end / query before and after evidence**，V4 那个反证中突然出现未列入 query-after 对照的具体问题不再出现。

### 仍然存在的实质问题

1. **OFF 主张和实验不完全对应。** 主假设还称中间位置会削弱 RAG 相对 parametric-only 模型的事实收益，但实验只有固定检索内容下的首/中/尾位置变化，没有 parametric-only arm。它能测位置效应，不能直接估计所声称的相对收益变化。末段又以 length-only 模型解释为反证，但固定长度设计没有提供该模型的估计方案。
2. **AUTO 换了一种未设计对照。** 主实验只列 decoder-only instruct 模型和 encoder-decoder reader，反证却要求比较 base 与 instruction-tuned 的相同模式；没有列入实际实验的模型比较仍然被用作反证。
3. **AUTO 的一个反证方向错误。** 它说较小的 encoder-decoder middle penalty 会削弱架构机制；但前文机制正是 encoder-decoder 因双向编码而更稳健。较小的位置损失通常与这个方向一致，不能未经额外预测就当成反证。
4. **替代解释未被充分区分。** AUTO 加 neutral filler 控制总长度，却没有控制 query 重复次数及提示语义；这不足以排除它自己提出的“更多 query tokens / 重复提示”解释。也没有事先给出显著性标准、效应门槛或样本设计，不能仅写 significantly 就称为可复现实验。
5. **原文范围仍被压缩。** 两臂都把 S3 的 retrieval collapse 概括为 RAG 的一般现象，省略“初步实验、部分任务如故事生成”的原始限定。将其与 long-context QA 位置偏差联系是待验证机制，不是论文已观察到的完整因果链。

开发判断：AUTO 提供更有针对性的启发，但关键实验闭合问题仍在，而且本题更贵更慢；不能交付为无需返工的研究方案，也不证明假设新颖或成立。

## 助手报告：旧错绑未复现，仍有错引与错误缺口

两臂都正确区分 RAG 的任务级 QA 结果与 MemGPT 的上下文管理/多会话评价，没有把异构基准直接排成胜负，也没有宣称已验证隐私隔离或长期私人研究工作流。AUTO 用 S9 保留 T5-comparable TriviaQA split 与 FEVER 两种分类设置，用 S10 保留 test-set sensitivity；这些具体条件有直接材料支持。

### 对 CuratedTrec 回归的精确结论

OFF 明确写 **CuratedTrec 使用 top-1000 retrieval 和 regex-matched supervision [S4]**，另述 TriviaQA 的划分。这与恢复后的来源一致，是本轮可观察到的正确使用。AUTO 没再把该预处理挂到 TriviaQA，但它根本没有展开这条预处理；所以只能说旧错误未复现，不能说 AUTO 已正确解释了该条材料，更不能由一次生成保证所有回指问题都已修完。

### 剩余引用/范围问题

1. **AUTO 架构细节挂错来源。** 首条把 seq2seq、dense Wikipedia index、pre-trained neural retriever 整句挂 S2；S2 只给预训练的参数/非参数记忆与结果等信息，完整具体结构实际在 S6。事实在本次材料中存在，不等于当前标签直接支持它；应拆主张或补 S6。
2. **AUTO 错误宣称词语缺失。** 末尾称节选不包含 assistant 等词，S3 却明确出现 personalized assistants，答案自身前面也已使用。后台 `uncovered_query_terms` 是词面覆盖提示且明确注明不代表概念不存在，不能被升格为原文没有该概念/词语的事实。报告仍把这类提示扩写成了用户看见的错误缺口。
3. **OFF 过度具体化 judge。** S5 确认 LLM judge，并在括号引用 GPT-4 与人评一致的既有工作；OFF 末尾进一步断言本实验使用 GPT-4 judge，单看这个可见节选不足以直接确认该型号。应保留原文支持的 LLM judge 表述或补足出处。
4. **OFF 将问题背景当最终结论。** 它多次将 RAG 摘要的 provenance / knowledge updating 开放问题表述为论文最终“留下未解”的结论；本次输入未提供全文的 index hot-swapping 实验，不能凭背景句判定整篇论文最终没有处理知识更新。

两臂依然缺少 external recall / archival 的完整定义、部分 DMR 会话与基线条件，未提供私人研究迁移、泄漏或访问控制的直接实测；报告中的“本次节选没有”不能外推为全文或领域没有。AUTO 省略一些 OFF 细节，输出和延迟下降，但仍有上述错误，不能据此判定质量/性价比全面胜出。

## 验收结论

本轮证明了修复代码确实进入真实请求：相同准备与付费输入、回指对象保留、完整交付、动态有界补查及成本记录都可核对。**软件流程门禁通过，回答质量门禁未通过。**

继续需要解决的是：不把词面缺口当事实；将具体主张挂到真正支持的来源；让假设、实际操纵、对照与反证形成可执行的一致设计；保留原文实验范围而非把局部观察泛化。提示合同存在不等于模型一定服从，不能把这两组回归包装为整体能力提升。任何下一轮修复、模型调用或评价都应另存版本和记录，不回写本轮结果。

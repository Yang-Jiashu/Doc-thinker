## 逐项来源审查

### 正确且真正用于判断的内容

1. **机制不再混淆。** 两臂将 MemoryBank 解释为 API 外的对话 / 摘要存储与向量查询，将 LongMem 解释为冻结 backbone 加可适配 SideNet、检索 token-chunk KV 的模型侧方案。S2 / S4 / S6 均直接支撑主要流程；“首版先做前者、暂缓后者”的路线与现成 API 约束相符。
2. **模拟条件保留。** 两臂明确 ChatGPT 角色扮演和虚拟用户，而非真实用户长时服务证明。没有编造 194 个真实用户、无限期记忆质量或隐私安全认证。
3. **消融没有直接冒充私人助手效果。** 两臂把 chunk-size=2 的结果限定为五个 NLU 数据集的 ICL；AUTO 末段明确现成 API 个人助手收益仍需拟议试验验证。
4. **方法卡不是论文证据。** OFF 明说 K1 为项目自编方法，AUTO 用 K1 支持验证流程并声明计划与已测结果分开。两臂均没有宣称测试已经执行或用户已经同意试点阈值。

### OFF：原文有出处，不等于没有需要核查的矛盾

OFF 写：训练采用 `65 tokens`，对 prefix 不超过 `65k` 的 ChapterBreak “过多”。S5 和原 PDF p9 确实印有这句；页面渲染确认并非解析器漏掉 `k`。但同一原论文 p6 §3.1 明确训练记忆容量为 **65k KV token pairs，固定容量 65536**，且 p9 消融候选为 `{8k,16k,32k,65k}`。这是论文内部的数字矛盾，不能记成模型凭空造数，也不能无提示地当成一致可靠的工程设置。应报告冲突、核对方法设置，而不是悄悄替原论文勘误。

OFF 又写平均 16k tokens 的文档“应对应”16k 缓存，继而以该条件建议首版固定小窗口。该来源讨论的是 LongMem 的特定容量选择，后文实验针对 PG-22；不能把这个例子升级为 API 外部文本记忆系统的通用容量规则。首版控制工程范围的建议可以成立，但与这个内部 KV 容量结论之间应明确是类比取舍、待验证，而非直接参数映射。

OFF 将 MemoryBank 的首版目标对齐“论文已验证”的共情回应。S3 展示 SiliconFriend 案例，S7 还明确心理数据调优是共情研究的一部分；原文 p5 的 open-source 变体进行了心理数据微调。不能据此隔离出“外部记忆检索本身带来共情提升”。这不推翻先做检索管线的主要决定，但需要收窄归因。

### AUTO：边界更谨慎，但仍有范围压缩

- AUTO 将 S1 的 `unlimited-length context` 直接列作 LongMem 能力，未说明原文 p4 的 memory bank 只维护最近 M 个输入、丢最旧 KV。摘要支持作者的说法，正文却说明有限队列机制；不能将“可处理持续流入的长上下文”读成“无上限永久保留 / 准确记住”。本答案没有进一步承诺个人助手无限保留，故本轮未把它判成改变路线的关键错误。
- AUTO 说 194 probes 用来评估“记忆召回和用户画像理解”。S7 将用户画像影响列为独立定性分析方向，194 probes 对应的是 broader-scale recall；两者不宜绑成同一个测验已验证的两项指标。15 / 10 / 194 数量和模拟性质本身准确。
- AUTO 用 S8 支持“MemoryBank 的遗忘曲线机制”，但这条实际摘录主要解释一般理论，没有完整更新规则及探索性限定。全文确有该机制，不能称其虚构；逐主张追溯仍应定位系统自己的应用段，而非让一般公式包办系统验证。

### 两版共同欠缺：论文怎么测、试点怎么判

两版都回答了“有何验证”的任务名称、案例和部分消融，但没有说明 MemoryBank 的人工 retrieval / response correctness / coherence 指标和三种模型变体比较，也没有讲清 LongMem 的 ChapterBreak suffix 选择 / accuracy、NLU 的任务及对照条件。AUTO 承认本次节选没覆盖大规模定量结果，较 OFF 谨慎；但“定性 / 模拟”与“有无定量评分”不是同一轴。原文对模拟历史另有量化人工评分；缺主表时应明确具体未知，而不是只报摘要里的显著改进。

试点表格确实有假设、基线、时间、指标与三类门槛，不能说完全没方案。但仍不能直接交给另一位工程师照表执行：

- OFF 没给样本 / 题目数量、历史窗口对齐办法；“显著高于”“可接受”“持续不相关”没有统计方法或可测条件。
- AUTO 提出 `5–10 个测试用户或场景` 且标待确认，是改进；但用户和场景是不同抽样单位。基线叫“无记忆连续对话”，未规定两臂当前上下文保留范围、是否对同一历史 / 同一问题配对，容易把窗口容量差异混进记忆机制效应。
- 两版的“正确召回比例”都未定义正确的判分标准、每题可核对事实、未知 / 错误回忆处理；个性化评价也缺统一量表与评审口径。
- AUTO 的通过条件仍为“有可测量提升”与“可接受”，停止条件为“无提升或超过预设上限”，但没有提出一个明确标注待确认的候选阈值或阈值确定步骤。标“待确认”避免了伪造授权，不能替代可执行设计。
- 两版都有“数据不足则补充 / 延长”而非硬宣成功，值得保留；不过两周内部数据不足的判断依据也仍需明确。

这些是原 rubric 的“实际验证”和“两周可操作试点”要求，不是读完答案后新增隐私、部署或统计显著性考题。本轮没有因答案未覆盖全部论文数字而单独扣分；扣分依据是关键评价方式和可复现判断口径缺失。

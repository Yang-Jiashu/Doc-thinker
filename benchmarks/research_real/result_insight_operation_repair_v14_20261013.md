### 设计题：真正召回时态正文，不等于模型正确保留条件

两臂已实际使用 S8 的四时间戳和旧边失效，S1 也由提示模板变成真实链接生成/读取方法。Zep S4 主表的 55.4%→63.8%、31.3s→3.20s、115k→1.6k，以及 A-MEM S3 的多跳 ROUGE-L 数字均有实际原文。没有把 Ps3 的角色指令当成用户命令执行。

仍有三类决定性缺口：

1. **时态条件被丢掉。** S8 / Zep PDF p3 明确在识别到 *temporally overlapping contradictions* 后才将旧边失效时间设为新边生效时间。两臂都改成“新旧信息矛盾时”直接失效，未保留有效时间重叠条件。涉及不同历史时期的事实不应仅因表面冲突就无条件互相覆盖；这会改变设计中的核心行为。AUTO 进一步说“保留历史但不影响当前回答”，S8 没有保证所有读取一定排除过期事实。该条件已经在输入里，不能再把问题归为该句未召回。
2. **整体实验被写成组件验证。** OFF 用 S4 的整体上下文下降支撑“社区检索能显著压缩”并把 S3 的整体多跳优势直接连到 embedding+LLM 链接机制；AUTO 在“理由（论文验证）”中用同一个 Zep 整体对照证明双时态边、三层图等单项。可以把整套系统成绩作为设计启发，但 Table 2 不是这些组件的逐项消融。AUTO S10 增加了 A-MEM LG/ME 消融材料，是比 OFF 更直接的证据；也不能反过来证明 Zep 每个组件或拟议混合系统的单独效果。
3. **试点仍不闭合。** OFF 指标保留 F1 / BLEU / 人工评估的多个选择，停止中的“显著下降”、不足中的“场景过少”没有固定可计算界限；AUTO 基线为“现有模块或 full-context”，未定其中哪个。AUTO 虽写分子分母，但分母是“实际作答且未缺失的题数”，将失败题排除后仅单独记录，会使两臂失败率不同情况下的条件准确率不再是同一配对任务完成率。通过/停止/不足仍有灰区：例如 +5 个百分点、P95=1.5 倍、token=70%、无缺失和失效错误时没有明确去向。它们都提供了有用框架，却还需补协议才能直接执行。

两版明确区分了拟议混合系统与论文任务，AUTO 还指出 A-MEM 具体 Memory Evolution 更新细节未全入本次节选、两个基准不同，不能互证总体优劣。这些限制表达保留；不因上述问题否认所有内容，也不将设计题自行追加成“两周必须完成”的要求——该题原文只要求小范围试用。

## 结论与可复核边界

本轮证明了关键原文能在既有预算内进入实际输入，并修正了生命周期误触发和模板占位；它没有证明模型能稳定保留原文条件、量词、单位和可执行门槛。材料齐了一部分，回答仍会把 overall 扩成每项最好、把有限 FIFO 说成不会遗忘、混淆块数与 token 数、把时间重叠条件略掉。继续同题重发直至得到满意答案会破坏本次验收，本轮没有这样做。

还剩供应商交付稳定性问题：low 和 8192 上限仍出现 HTTP 200 空正文。失败收据应保留并对用户显式报错；本次既不增加花费掩盖失败，也不把它误归因成检索质量已经验证失败。单次故障不能推出供应商普遍不可用，四份完整答案也不能证明客户可直接用、长期任务胜任或 RSI。

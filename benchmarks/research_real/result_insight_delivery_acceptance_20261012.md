# Insight 真实论文验收：模型返回、实际交付与质量分开核验

2026-10-12。**来源契约修复后，V3 一组真实 OFF/AUTO 回答通过端到端交付门禁；答案质量与稳定性仍未全面验收。** V1 的空回答和 V2 的三个 AUTO 撤回均保留，不能用后来的单题成功抹去失败或宣布普遍算法收益。

## 比较的是什么

`--contrast insight` 两臂均使用真实 `ResearchService`、固定哈希的公开论文 PDF、静态知识卡和原有后台材料辅助。只切换 `insight_mode=off/auto`，不关闭整个辅助系统。动态约束与静态卡共享预算，最终保留的完整卡数可能变化，必须以实际输入回执为准。

三题分别覆盖文献比较、可检验假设和助手方案报告，材料为 RAG、Lost in the Middle、GraphRAG、MemGPT。它们是**有意覆盖已知触发词的开发 smoke 题**，不是未见题或泛化测试。原有 `research_papers_ab_v1.json` 的 13 个问题经当前生产路由检查均没有匹配 Insight pack；该覆盖缺口尚不能由三题 smoke 消除。没有读取封存 holdout，没有给回答模型提供伪造标准答案。

## V2：六个模型回答成功，但三个 AUTO 没交到用户手上

本轮两臂统一使用生产任务预算：有原文的研究任务最多 8192 completion tokens，普通聊天仍为 2048；不是无限输出或自动续费。温度显式设为应用默认的 0.1，不读取或代表任意用户的私人温度配置。Step 5 官方端点的 `reasoning_effort=low` 由生产共用参数构造器给出，runner 不再单独增加该字段。

六次请求均 HTTP 200、`finish_reason=stop`、实际模型 `step-5-preview`，供应商都有非空正式 `content`。但 AUTO 的实际 `result.answer` 是资料撤回占位，`sources=[]`、`knowledge_skill.status=unavailable`、`reasoning.status=source_unavailable`，并有 `provenance_unavailable` 警告。**原始 provider.answer 不能代替产品实际交付的答案。**

### 故障归属

Insight 允许在基础八条来源后追加至多两条，实际生成输入有十条来源；旧持久化及客户端来源契约仍只接受八条。生成之后保存依据失败，触发了既有的安全撤回逻辑。所以这是**来源数量契约不一致的端到端软件故障，不是这一轮模型未生成，也不是已经证明的推理质量下降**。不能通过关闭撤回保护或把 provider.answer 冒充最终答案来“修复”。

修复方案统一最终来源契约为十条，基础召回仍为八条，补充仍至多两条，总原文字节预算仍为 12,000；同时保持撤销、跨会话隔离和历史失效保护。下文分别列出三份离线交付回放和一组新真实生成复验，不将二者混为同一种证据。

## 评测器也必须验证交付

运行结束后新增统一交付门禁：

- provider 成功，但答案为空、来源依赖不可用或依据无法确认，独立记录 `delivery_failed`，停止后续付费调用，保留真实 provider usage。
- 汇总不再把未知交付状态折成 completed；分析器也重查旧记录，而不是盲信旧 status。
- 部分来源撤回但仍有正常答案和有效来源可进入质量审查；普通漏引用、错误引用、弱证据仍是质量缺陷，不能以筛除它们来抬高分数。
- response_shape v2 将旧 `len(strip)` 明确命名为 `stripped_characters`，并另算真正的 `non_whitespace_characters`。V2 实验记录使用的是旧 shape v1，其字段语义不回写；任何版本均只记录形状／长度，不记录 reasoning 正文。

门禁修改后相关测试 **123 passed**，包括旧 completed 记录重新判定、provider 成功但实际撤回的真实服务路径、费用不丢失、交付失败立即停止、普通质量缺陷不被错误筛除。它们是软件契约测试，不是生成质量评分。

## 三份同输入离线回放：验证交付，不重算生成质量

修复后，对 V2 三个 AUTO 任务各执行一次真实服务回放，writer 返回原先已经付费取得的正式答案，不再请求模型。三份完整入模消息的 SHA256 均与对应原始付费请求严格一致，包含相同原文摘录，不能用不同输入掩盖原故障。

- 三份均返回并保存十条来源，无持久化错误；保存后 `hydrate_history` 可读完整答案和来源。
- 撤回 S10 所属文档后，相关分析依赖关闭；没有通过放松撤销保护换取交付成功。
- 每份 recorded writer 调用 1 次、实际 provider 调用 0 次。它们是同输入交付／撤回回归，不是新的模型生成、独立质量样本或稳定性重复试验。
- 手工回放没有执行真实进程重启。另有重新创建 `ResearchStore` 实例读取十条引用的单元测试，不能据此写成整套产品重启已实测。

材料位于 `dist/insight-provenance-replay-v2-20261012/`，`summary.json` 保存三份原始／回放消息哈希、交付和撤回检查结果。V2 原回答记录仍保持当时的失败状态，不替换成回放结果。

### 非盲开发审查：有新增可用材料，也仍有明显缺陷

一名 AI 开发审查者查看了 V3 正式答案及实际来源；知道开关，没有随机候选顺序、独立参考事实或正式评分，不能代替盲评或人工专家结论。其具体观察为：

- AUTO 新增并使用 S9 的 C0–C3 社区层级及比较条件，以及 S10 的两语料约百万 tokens、问题类型／规模／终端用户验证局限，确实补充了方法和外推边界。
- 输入仍保留 S5 的泛化背景与 S8 的参考文献列表，原始 RAG 的核心方法片段仍没有召回；不是“证据漏召回与噪声都已解决”。
- AUTO 关于知识密集 QA／FEVER 竞争表现的合并表述超出 S3 中直接给出的 FEVER 定量证据；知识图谱＋RAG＋QFS 的组合说明在 S1，回答却挂 S4，存在引用定位问题。部分“缺少比较”的表述重复。
- OFF 对绝对得分和显著性缺失更明确。综合这些差异，不能仅因 AUTO 多两条来源或更快，就判定其整体质量胜出。

程序报告引用标签有效、不含撤回警告，只代表结构与可用性检查通过；**没有证明每句话都被所挂引文支持**。

## 当前可交付结论与仍需验证的事

可以确认：本次来源数量契约故障已通过三份严格同输入回放和一组新真实生成复验；真实 provider 消耗、输入预算、交付失败与成功能够分别记录。

不能确认：Insight 普遍提升回答质量、稳定节省 tokens、原文核心事实全部召回，或产品已通过手机端、生产并发和全场景上线验收。下一步仍需补关键方法证据、过滤低价值背景、对齐结论与引文，再做有成本边界的多题重复盲评；不能用扩大来源数量或更宽输出上限代替算法质量。

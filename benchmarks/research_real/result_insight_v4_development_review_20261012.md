# Insight V4：三组真实论文开发对照复验

2026-10-12。**六次真实请求均完成交付，形成三组有效对照；核心方法已能进入答案，但动态 Insight 尚未达到“稳定更准、更省、更快”的标准。** AUTO 带来了部分额外的有效比较与假设依据，也出现了明确的对象错绑和实验条件不自洽；本轮总 token 比 OFF 多约 36%，三题都更慢。以下保留这些失败，不以软件门禁通过代替质量通过。

## 比较范围与口径

本轮比较动态 Insight **OFF / AUTO**，两臂的普通后台辅助和静态知识卡均启用，不是“整个后台辅助关 / 开”。实际保留的方法卡可能因共享预算变化，以最终入模记录为准。

沿用三题开发 smoke、四篇固定 PDF：RAG、GraphRAG、Lost in the Middle、MemGPT。问题有意覆盖已知触发器，前轮结果已经看过，因此这是**开发 AI 的非盲逐来源审查，不是独立专家评审、封存 holdout 或统计显著性检验**。不使用生成参考答案或自动关键词覆盖率冒充质量标准。

实际运行目录：`dist/insight-deploy-smoke-v4-20261012/`。冻结准备目录：`dist/insight-deploy-smoke-v4e-prepare-20261012/`。准备、正式开始、正式结束及运行清单指纹均为 `6e5e803cffbdee0dc60c43219aae4ee484e60601c358b61fb61dbfa9bbd89542`，由本轮 `protocol.json` 和各请求回执核验。没有改写旧 V1–V3 的成功或失败记录；运行之后的修复不归入本轮版本。

审查标准在新答案产生前写入 `plan_insight_v4_development_review_20261012.md`：实际完整交付、核心方法/条件覆盖、严格整条背景/参考表与混合噪声、逐主张引用、范围与未知、用户任务完成，另外记录真实 token 与延迟。来源存在或引用标签合法，不等于语义支持已验证。

## 运行与交付

实际为 **6 次请求、6 次 provider 完成、6 次完整交付、3 组有效配对**。全部 HTTP 200、实际模型 `step-5-preview`、`finish_reason=stop`，交付门禁均 passed；unknown usage 为 0、自动重试为 0、无停止错误。本轮没有发生 V2 的十条生成来源被八条持久化契约撤回的问题。这一轮没有额外测试真实进程重启，不能将历史持久化单元测试写成本轮重启实测。

逐份比较确认：六次实际 `prompt_digest` 与冻结准备相同；交付的 source_quotes 投影也与准备包逐字段相同，包括文本、标签、页和节选坐标。每个 OFF 保留八条来源，AUTO 保留十条；两臂静态卡均 ready。AUTO 实际注入动态约束并各完成一轮有界本地补查，OFF 不注入、不补查；辅助算法未追加模型请求，每次只有一次回答模型请求。

本轮 OFF 各保留两张静态方法卡，AUTO 因共享预算各保留一张，新增动态约束分别为综述 291、假设 298、报告 295 字节。因此比较的是 Insight 启用后的整条生产流程效应，**不能单独归因于某一句提示或某一条补充来源**。

实际任务 completion 上限 8192、显式温度 0.1、semantic 关闭；Step 官方端点参数沿用生产共用构造器。协议最多六次请求，100,000 reported-token 观察后软停止，不是供应商硬费用保证。本轮实际 53,504，未触及阈值。fixture 中的 80,000 为上一轮旧协议文字，本轮实际协议由 `protocol.json` 单独明确记录。

实际运行的普通辅助 scheduler 均 completed，AUTO 的本地补查也 completed；与 prepare-only 的 `not_observed` 区分。大部分模型前处理约 0.47–0.52 秒，假设 AUTO 为 1.350 秒，其中普通辅助 worker 约 865.56 毫秒。它不是“所有前台开销都小于 1 秒”的证据。流程耗时不含预先摄取与文档预热，也不是首 token 延迟；各 arm 的设置成本另存在回执中。

这些只是一次开发运行观察。问题数少，未控制供应商负载与生成随机性，不能据此推出普遍的速度、费用或质量因果结论。

## 逐对源文审查

### 文献比较

两臂都正确描述了 RAG 的 seq2seq 参数记忆、Wikipedia dense index 与同序列/逐 token 两种形式，引用各自 S1；GraphRAG 的实体图/社区摘要和 map-reduce 分别挂 S8/S2。V3 中没召回原始 RAG 核心方法、方法组合错挂无关 S4 的具体问题在这一题未复现。因为检索和回答合同同时改变，这不是对单项修复的独立消融证明。

AUTO 的可用增量是：用 S9 补充六个比较条件的窗口大小和生成提示控制，保留了 reference-style 小修改这一例外；更清楚地区分 GraphRAG 的“naïve RAG”对照和原始训练式 RAG，并引入 S10 对检索结果排序先验的稳健性检查。两臂都说明任务/指标不可直接排名；AUTO 对“本次节选缺口不等于全文或领域缺口”的表述更明确。

仍有范围压缩风险：S2 对相对 source-text summarization 的好处限定为中/低层社区与相应指标，两臂结论段都写得更概括。不能将其读成所有层级、全部基线和全部问题都更好。S10 的明确洗牌动作和复测结果在原文下一块，当前节选主要有标题与修改排序提示的说明；这也提示稳健性条件并没有完整进入输入，不能凭这一条声称已覆盖完整受控实验。

开发判断：AUTO 有具体额外信息，方法/评估区分较完整，但更长，费用与延迟大幅上升；不足以声称整体性价比胜出或所有引用问题已解决。

### 可检验假设

两臂都完成了“一个假设、原文观察、机制、替代解释、反证实验”的基本结构。AUTO 利用新增 S10 的 query-aware contextualization 材料提出“位置 × 查询条件化”的交互，并明确将跨论文机制连接标为未验证；这比 OFF 的一般位置/注意力猜想有更具体的资料入口。它把 key-value 结果标在对应任务上，没有直接宣称多文档 QA 已验证同样收益。

但实验不能直接拿来执行：

- **OFF** 假设同时预测随长度增强、instruction-tuned 比 base 更强，实验却固定总长度，比较 RAG 与非检索模型，而没有设计长度变化或 instruction/base 对照。把“非检索模型位置效应同样强”当作反证，也不能反驳其最初那个并未要求 RAG 更强的位置假设。
- **AUTO** 实验列出 query only at start、每段前后重复 query 和 encoder-decoder 条件，反证段却使用未列入设计的 decoder-only query-after 基线。比较条件命名不一致会直接阻碍实现；重复 query 和跨架构对照的 token/模型差异也需要明确定义控制，不能仅写“恒定总 tokens”就算完成。
- 两臂引用 RAG 的检索塌缩时都省略了原文中“初步实验、部分任务如故事生成”的具体范围。将该现象拿来作为所有 RAG 或长上下文 QA 的已观察原因会越界；它最多是带范围的旁证或候选解释。

开发判断：AUTO 的假设更有针对性、推测标记更清楚，但仍需修正实验对照的一致性。没有证据证明该假设成立、新颖或已优于现有研究；不能称作无需返工的研究方案。

### 私人研究助手报告

两臂都恢复了 RAG 基本架构，说明 MemGPT 的层级/函数/事件式上下文管理和主上下文三个组件，并正确列出所见 DMR 问题生成与 ROUGE-L / LLM judge 评价。两者都将隐私隔离、访问控制、真实研究工作流和同条件 head-to-head 视为本次节选未证明的迁移事项，没有把长期记忆等同于已验证的隐私安全。

AUTO 额外纳入了 FEVER 的 3-way / 2-way label accuracy、TriviaQA 的 T5-comparable split 和两种测试划分差异。这些补充有对应来源，但也出现了**明确错绑对象**：

> AUTO 将 S4 中 top-1000 retrieval 加 regex/heuristic supervision 描述为 TriviaQA 的预处理。

回查本轮公开语料 `rag.pdf` p18（存储 ordinal 44）：这个 regex 段属于前面的 **CuratedTrec preprocessing**；后面才进入 **TriviaQA Evaluation setups**。实际 S4 从该原始块的字符 959 开始，开头是回指前文的 “To overcome this”，省略了 CuratedTrec 标题和前提，却保留了后面的 TriviaQA 标题。模型因此给出真实标签但错误的数据集对象。**标签合法和正文可回溯没有防住语义错绑。** OFF 只使用 S4 后半段的 TriviaQA split，没有作出这个错误的预处理归属。

其他边界仍需保留：external recall / archival 的明确定义和部分 DMR 会话/基线条件没有被提供，两臂没有补全它们；MemGPT 的概述性胜出不能替代缺失数值或受控对照。RAG 摘要中的 provenance / knowledge updating 问题背景也不宜直接当成整个论文最终未解决的结论；完整原文另有 index hot-swapping 实验，而本次输入没有覆盖它。

开发判断：AUTO 增加了评价细节，但引入一个可定位的实质性错误，而且更慢更贵；这对不支持“AUTO 整体更好”。两者均不能据当前材料给出私人助手能力或隐私保证。

## 结论与剩余问题

本轮完成了三组真实模型、真实论文、真实生产服务的有效比较，确认修复后的核心材料能进入回答、十条来源可以交付，并看到动态补查的实际信息增量。它也明确暴露了尚未解决的问题：

1. 回指片段不能丢掉前面的对象/标题，否则会出现“引得出原文，却归错对象”。
2. 生成的实验要核对假设因素、操纵条件、基线和反证条件是否一一对应，不能只检查结构字段齐全。
3. 有额外材料不代表值得生成更多内容；本轮 AUTO 三题均增加费用与完整响应耗时，尚无质量/成本净收益证据。
4. 继续保留外部存储细节、完整实验条件、隐私和迁移能力的未知，不用“有来源”包装成全面验证。

三题是已知开发集、每臂仅一次生成；不能推广为跨模型、跨领域和大规模客户场景的结论。下一轮若修改回指保护或输出/实验合同，必须使用新运行目录与新版本，单独报告，不能回写或合并为本轮同一实验。

# 组件定义召回复验 V6：证据用上了，答案质量尚未全部过关

2026-10-12。两次真实 `step-5-preview` 请求均完整交付，组成一组有效 OFF / AUTO 对照。新召回的 MemGPT recall / archival 定义确实进入了回答；两臂也都正确引用了 RAG 的具体架构来源。但 AUTO 又把 TriviaQA 的测试集差异放进 FEVER 小节，并在总结中将 FEVER 也说成达到 SOTA。**本轮软件交付和指定结构召回通过；逐主张归属、实验范围及整体答案质量仍未全部通过。**

## 预登记范围与运行一致性

这是已经看过前轮问题的、来源导向的非盲 AI 开发回归；不是新题、封存集、独立专家盲评、多模型评价或整个产品验收。本报告不覆盖 V4、V5 历史记录，也不把不同源码版本合并成同一实验。

## 仍未通过的质量项

### 1. AUTO 把 TriviaQA 的测试集差异放到了 FEVER 下

AUTO 的 FEVER 小节先正确描述三分类 / 二分类和不使用检索证据监督，随后紧接着用 S10 说 official Wiki test set 比 conventional open-domain test set 更好。S10 开头的 “both test sets” 回指的是 TriviaQA；对应先行对象在 S4 的 `TriviaQA Evaluation setups`。S10 后半段才以 `E Further Details on FEVER` 切换任务。

因此这不是来源完全缺失，而是**有来源、但把跨段回指绑到了下一任务**。AUTO 没有在该句注明 TriviaQA，将其置于 FEVER 项下会让读者误认为是 FEVER 结果。相比 V5 的 CuratedTrec 修复，本轮暴露了另一个同类对象绑定问题，不能只靠增加定义覆盖解决。

### 2. AUTO 将局部 QA 结果扩大为 FEVER 也达到 SOTA

AUTO 总结称 RAG 在 open-domain QA 和 FEVER 都达到 state of the art，并挂 S2 / S9 / S10。S2 给 QA 结果；S9 的 SOTA 句明确针对四个 open-domain QA 任务，且保留 TQA split 限定；FEVER 部分只说明分类设置、指标和监督方式。S10 也没有给出 FEVER 的 SOTA 结果。

这个复合结论超出实际被引节选的支持范围。正文曾正确保留 TQA-comparable split，但总结仍把任务和结果合并，说明“正文有条件”不能替代逐主张、逐任务的最后核对。

### 3. 两臂仍可能将引言背景升格为论文最终限制

S7 的 provenance / world-knowledge updating 句属于引言问题背景。OFF 在缺少的比较中进一步写 RAG explicitly leaves updating world knowledge open；两臂也把这句列为 open problems。单凭当前摘要节选，不能据此判定论文最终没有研究知识更新。

正确边界应是“当前可见材料尚不足以判断该能力”，不能把引言提出的问题直接当成全文最终结论。本轮输入仍未提供专门的更新实验，评价也没有把未召回的全文事实偷偷当作模型已经看到的证据。

### 4. AUTO 的静态 / 无上限表述和一个实验对照仍需收窄

- AUTO 将 RAG 的 Wikipedia index 称为 fixed / static。来源支持所用语料和索引结构，但“当前节选没给增量更新实验”不等于索引在技术上只能静态使用。
- AUTO 将 MemGPT 的强项说成已经 demonstrated managing unbounded conversational history。来源提出有限窗口管理可扩展外部上下文的架构，并报告有限实验；这不能证明无限历史上的质量或资源表现。答案后面虽承认需要长时实验，前面的 demonstrated 仍偏强。
- AUTO 表格要检验“MemGPT 自主编辑优于 static RAG retrieval”，对应最小实验却只有 MemGPT 开 / 关 self-editing，没有列入待比较的 RAG baseline。该消融能测编辑模块增益，不能单独支持表格所称的跨系统优势。

这几项与 V5 假设题的具体答案不同，但仍说明任务、比较对象和实际实验必须闭合。软件成功生成表格不代表实验已可直接执行。

## 范围控制、噪声与可用性

两臂都明确表示没有共同任务下的 RAG-vs-MemGPT 直接实验，不把异构基准直接排胜负；也都区分私人助手迁移设计与已验证结果，未宣称已证实隐私隔离、访问控制或合规。V5 的“assistant 一词不存在”错误没有复现。关于这些边界，本轮表述总体更谨慎。

两臂都完成了报告任务，不是纯检索清单。但仍多次重复“缺直接比较 / 缺私有部署 / 需要实验”，AUTO 增加的表格并未消除全部对照错位；OFF 对引言开放问题也有重复外推。不能把输出有标题、引用和表格等同于无需返工。

**不能解释为“答案更短，所以更省”。** 正式可见正文 OFF 为 8,259 字符 / 1,124 个空白分词，AUTO 为 8,346 字符 / 1,151 个空白分词；AUTO 的可见正文略长。供应商 completion 用量与可见文字长度不是一回事，reasoning_tokens 上报 0 也不证明没有内部推理。这次只读取正式答案、来源及安全用量 / 响应形状元数据，没有读取或保存供应商推理正文。

每臂只有一次采样，AUTO 还有 768 缓存 tokens，输出随机性、缓存和供应商服务时间未严格控制。因此只能报告这次更省、更快的观测，不能证明通用速度或成本收益。前处理约 550–571 毫秒，两个 scheduler completed；完整流程不包含本轮共用的约 1,044 毫秒文档摄取，也不是首 token 延迟或高并发结果。

## 自动检查没有替代语义验收

两份实际 `claim_audit` 都是 `review_needed`、`entailment_verified=false`，各处理十二段，OFF 另有 45 段、AUTO 44 段在窗口之外。自动 issue 数分别为 19 / 15，但其中含通用条件、否定措辞或无引用提醒，不是错误率或质量分数；不能据 issue 数较少判 AUTO 更准确。上文跨任务错归、SOTA 泛化和实验对照问题来自对正式答案与来源的独立开发审查，不是已完成的自动全文语义验证。

## 验收结论

**通过：** 真实模型与生产路径、冻结输入一致性、完整交付、来源坐标、预算和有界调度；指定缺失结构进入输入并在正式答案中被使用；本次 RAG 架构引用、OFF CuratedTrec 归属正确。

**未通过：** 全部关键条件和对象绑定、总结里的逐主张支持、所有拟议实验的对照闭合，以及“报告无需返工”的质量目标。新增定义召回解决了一个真实缺口，但不自动解决跨段回指、证据范围与模型生成的错误。

这是一题两次调用的定向回归，不能声称 AUTO 整体优于 OFF、全部算法达标、跨模型泛化或产品可以直接全面上线。后续修复与调用应另存新版本及结果，不回写本轮原始记录。

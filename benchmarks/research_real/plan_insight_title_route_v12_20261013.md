# 标题软绑定、自然交付路由和结论边界：开发复验 V12

2026-10-13。写在本轮新模型调用前。V11 原论文两臂 72.50/71.25 均未通过原 80 分门槛；新增 A-MEM/Zep 材料在冻结后揭示，设计题输入完全相同而不付费，短报告题已经执行唯一配对。所有原登记、输入、答案和失败保留。现在两份新增论文也已曝光，V12 复用只能称开发回归，不能再称未见材料验证。

## 问题和修复边界

1. 用户按论文技术名提问，但通用文件名不能绑定原文标题，章节角色候选缺失；反复自称名称和图轴挤占方法、测法及主要结果。只从每文档最早页、首块有限标题区的明确技术名—副标题结构提取软名称线索，用户须明确提及，重名保留歧义；正文、引用和资料指令不得成为标题。原文标题定位只提供有界候选/覆盖提示，不授权资料访问、不提供事实、不是一般实体识别。不能用论文名字、答案数值或评审定位器硬编码。
2. “结合论文里的验证”和自然写作/设计建议不稳定触发实验目标与后台方法。依据有限用户请求语法修正，先隔离引号/代码/显式资料块，保留逐字任务、否定、未知和高风险门禁。不把所有聊天都变成必须运行的方法，不增加生成、翻译或嵌入请求，不用固定题干强制激活。
3. 已给材料仍会被错误概括：总体最好扩大为每项最好，外部编码/索引混同生成 API 的内部访问。共享模型中立合同 v8 明确区分。拟议试点各对照配置须明确固定、不留可替换分支，不禁止合法多基线；三规则必须互斥、覆盖中间区间，灰区给明确补证操作，缺失与失败不静默从分母排除。这是生成指导，不是语义验证器或已执行实验。保留原 3800 字节系统合同上限，用精炼而非扩大上下文实现；仅版本断言更新，原内容及预算断言不弱化。
4. 首次零调用准备暴露了另外两层缺口：静态整理可以用同一片段 ID 的较窄窗口替换已经选中的正文，旧丢失检查却只比较 ID；同分候选的短窗偏置也会挤掉有互补角色的正文。修复须比较实际原文区间、沿用可靠标题头部边界，并让既有互补窗口在原配额内竞争。明确询问作者联系信息时可以保留相应元数据，普通方法任务不能因此召回邮箱。首次准备记录保留为诊断，不冒充修后验收；修后准备使用新的目录，不覆盖失败。

先写陌生合成材料和正负例，再改实现。保留原图注、标题、引用、狭义查询、来源撤回、同名资料、不同任务及预算测试。定位器只在离线验收原文，不进入检索或模型输入。保留因果、对象、任务、指标、对照与适用范围，不以更多 source 或引用算成功。

## 固定边界

- primary 4096 块扫描、48 候选、最多 8 基源，补查 256 块/48 池、最多 2 条/2400 追加字节，全部最多 10 条/12000 原文字节。
- 实际消息最多 24576 UTF-8 字节；词面辅助非排队前台等待仍 1 秒，缓存仍请求局部且有限。不扩大池、等待或输出上限来修复。
- 普通生成一次，零额外模型检索/验证、零重试/续写/替换，semantic off。保留静态方法及 Insight 预算竞争，实际卡片差异须披露。
- 三个自然题分别为原 MemoryBank/LongMem 路线题和原封存 A-MEM/Zep 设计/短报告题；两套 fixture/四份原 PDF/问题/六维 rubric 逐字保持。不删差题，不按答案选择样本。

## 实测协议与门槛

单元、实际原文来源及调度核验后，另写正式注册，记录代码、合同、两个 fixture、原封存协议、本计划、四 PDF 哈希，冻结实现。每题只一次配对，最多 6 个顺序 Step Plan `step-5-preview` 请求；温度 0.1、low reasoning、非流式、生产研究输出 8192 tokens、180 秒、零重试。65000 个供应商上报 tokens 为观察后软停，不是硬费用上限；用量未知/派发不确定/失败时停止并保留，不补齐。

先零调用 prepare，实际适配器 socket 派发前只读核对实际消息摘要与验收 prepare，一致才发；不改原文、消息或参数。不一致中止且不重跑挑选输入；OFF/AUTO no-op 则该题不付费且保留，不改题硬触发。记录模型前、中、后、完整时延，摄取/复制/预热单列；缓存和单次顺序差异不能代表普遍降本/提速。

## 3. 逐项答案审查

### 已真正做好，而不只是输入命中

两版都区分了外部文本记忆与模型侧 KV / SideNet，建议先做可独立实现的存储、摘要、检索，暂缓内部模型改造，没有声称在普通生成 API 上能直接训练 SideNet。模拟用户性质、15 / 10 / 194 条件和三个指标都进入了最终答案。两版明确拟议试点及候选阈值待确认，未声称已执行或已获授权。

AUTO 正确使用新增材料说明冻结 backbone 与适配训练；Table 3 中 LongMem 37.7% / 39.4% / 40.5%、MemTRM 28.3% / 28.7% / 28.7%、GPT-3 28% 和 558M 参数均与表一致。这是有效增量，不应因最终失败而说辅助完全没作用。

### AUTO：把整体表现改写成所有指标最优

原回答写“ChatGPT 基座变体在各指标上最好 [S7]”。S7 实际只说该变体整体最好、各指标表现高，并没有说每项均第一。原 PDF p9 Table 2 给出直接反例：

| 检索准确率 | ChatGLM 变体 | BELLE 变体 | ChatGPT 变体 |
|---|---:|---:|---:|
| English | 0.809 | 0.814 | **0.763** |
| Chinese | 0.840 | 0.856 | **0.711** |

因此不能把此句归为“仅省略细节”：它新加了原文没有且与原表冲突的实验优胜结论。ChatGPT 在正确性、连贯性和 ranking 上较好，不代表检索也最好。输入未含数值表不允许扩大 S7 的定性范围；原文表格审查进一步确定了错误。OFF 的“在各指标上表现高”没有同一项全称错误。

AUTO 保留了其他指标受基座能力影响这一提示，值得保留；但两版都没有明确说明三种带 MemoryBank 的模型变体比较，不等同于控制基座后的“有 / 无记忆”消融。可转述作者观察及通用性主张，不能把它当成外挂记忆单因素、所有开闭源模型的已证因果收益。

### LongMem：数字正确，比较范围仍要说清

AUTO 的 Table 3 数字及 AO3 / 零样本 / 前缀长度准确，不是错表或虚构数值。但 GPT-3 等带 † 的基线是引用既有研究，模型参数、local context 和内存方式不同；LongMem / MemTRM 是把 4k/6k/8k 放入 cache、local context 仍 1k。应写“论文该设置下表中准确率更高”，而不是让“显著优于”暗示同参数同资源对照或统计显著性。本摘录没有给该比较的显著性检验，不能单凭中文“显著”认定其做过统计检验。

AUTO 的 PG-22 / ArXiv 困惑度改进概述有 S10 和原论文 p7–8 支持，但比较主表与完整条件不在它的输入内，不宜继续外推。OFF 则把所见验证缩写成小说续写类任务；LongMem 原文还含 PG-22、ArXiv、NLU 和问答，应限定为“本次节选中的 AO3 后缀选择验证”。这不证明私人助手迁移收益，两个答案在这一迁移边界上都基本谨慎。

### OFF：把可替换编码器与生成 API 的接口混在一起

OFF 最后写“现成模型 API 可能不暴露 query 编码所需接口”，并以 S1 为依据。S1 说明 E(·) 可换成任何合适编码器；它没有要求 query 必须由回答用的生成模型 API 暴露内部状态来编码。产品应验证独立文本编码器 / embedding 服务的可用性、语言质量与成本，而不是由“生成 API 不暴露编码接口”推出 MemoryBank 难接入。

原 PDF p5 的实现进一步明确使用 LangChain 支持的开源 embedding 与 FAISS，英文用 MiniLM、中文用 Text2vec。这段未进入本轮模型输入，不能补算成它已经引用了正确实现；它为独立审查提供了外部编码器与生成模型不同的直接证据。

该句是可能性风险，不是明确断言整个首版不可行，前文还正确推荐外部管线，因此本审查不将它升级为路线已被完全推翻；但它会给团队造成不必要的架构疑虑，方法和建议还需小修。OFF 对 LongMem 需要训练的前提亦不如 AUTO 明确。

### 两周方案：数值门槛出现了，但决策仍没有闭合

OFF 已固定相同模型版本 / 参数、同历史和问题集，给出 50–100 个问题、两名工程师背靠背评分及平均分；AUTO 则提出 5–10 个虚拟用户、3–5 天记录、50–100 probes。两版均给了 +0.2、0.7、0.5 等待确认建议值，较仅写“显著 / 可接受”有实质进展。

但仍不能把方案不加解释地交给另一组人执行：

1. **中间结果没有去向。** 假设样本充足、正确性提升 +0.10、检索准确率 0.60、连贯性持平，没有隐私或运行事故：两版都未通过通过规则，也未触发停止规则，又不能说数据不足。需要事先明确这类区间是未通过、进入限额迭代还是收集哪类新证据，不能现场改门槛。
2. **AUTO 未固定配对口径。** “相同 API / prompt 模板、不接记忆（或仅最近 N 轮）”存在两个基线，N 未定；同一历史、同一问题、模型版本 / 参数、当前窗口范围均未明确。两条路线容量不同会混入效果，不是单看记忆模块。OFF 在此明显更完整。
3. **判分和失败分母仍欠缺。** 有量表数字和原文引用，但没有把正确 / 部分正确的目标事实、无法回答 / 错误回忆 / 超时的处理与计分分母写清。AUTO 又提供“人工标注或 LLM 初筛抽检”两种未统一办法，未规定复核 / 一致性口径。不能把有三个指标名称当成同一套可复现测法。
4. **不足分支仍有模糊部分。** AUTO 给出 probes 少于 30 的可计算条件，但“标注一致性过低”没有定义；OFF 的“样本过小 / 历史覆盖不足”更笼统。AUTO 的“隐私 / 延迟不可接受”也未量化。没有把这些条件当成已授权阈值是正确的，但“待确认”不能替代完整候选方案。

这些仍属原 rubric 的“两周内可操作检验”要求，不是事后增加新的上线或统计显著性考题。并未要求用模型替用户决定阈值或自动实施实验。
